# cEDH Tutor / 竞技EDH导师

微信小程序原生项目，辅助 cEDH / EDH 玩家测人格、匹配主将、记录战绩、试玩牌组与管理牌桌。对局工具仍以本机数据为主；新增“EDH hub”使用微信云开发处理用户主动提交的名片、投票与牌桌确认。草稿、战绩、赛后复盘和调牌记录保存在本机，不会自动上传。卡牌搜索与卡图由 Scryfall 提供；强度分析仅向 Scryfall 发送去重后的英文卡名，不向项目后端上传原始牌表。运行时不请求 edhtop16 或 Reddit。

品牌导出物使用黑底赛博风格的 `cT` 字标（母版见 `tools/logo-export.html`）；应用主页使用荧光黄绿的点阵索引页，以 `cEDH Tutor` 为主标题、「竞技指挥官导师」为中文副标题。

界面改动的判据见 `docs/ux-goals.md`（产品体验准则）：提改动时先说明它服务哪一条准则、又牺牲了哪一条；该文档同时记录了首次逐条对照审计的结论。

预商业化审查与后续放行条件见 [docs/precommercial-review.md](docs/precommercial-review.md)；Planechase 的规则、恢复与验证记录见 [docs/planechase-review.md](docs/planechase-review.md)。竞逐时空的界面一致性、交互及验收记录见 [docs/planechase-atlas-design.md](docs/planechase-atlas-design.md)。

竞逐时空文案遵循「每处提示只说明当前操作」：移除重复标题、装饰中点和底栏圆点，按钮使用简短动作词，掷骰费用在主按钮内并排显示。规则正文保持完整；响应时机、置底顺序及存档失败提示仍保留。

竞逐时空显式覆盖微信 `style: v2` 按钮的默认宽度和禁用白底，卡图按钮另设整行宽度，避免绝对定位内容在 `width: auto` 下收缩为零。人数与牌库余量收进标题下方，骰子读数和新回合控制置于卡文前；改判说明与结果分行。背景挂载与混沌工具同色的粒子组件（`palette="random"`），正文包在 `content-layer` 内，面板及按钮沿用共用暗色 token。单条能力统一从底栏结算，多条能力仍逐条选择；保存失败后滚动到重试和取消入口。布局验收包含微信原生按钮样式及放大字体，普通 HTML 按钮预览不足以发现这些差异。本轮技能来源、取舍及评审复现见 [docs/planechase-skills-review.md](docs/planechase-skills-review.md)。

## 当前模块（19 页）

“EDH hub”由首页底部统一入口进入，使用独立 `community` 分包，包括入口页及五个功能页：

- **三张牌认识你**：每位玩家一份名片，不按主将或套牌拆分；中英文搜索、实际印刷版本及语言选择、全卡或卡画图片导出。署名和短评选填，填写提示用“看一眼就心动的那张”这类让人想分享的问法，短评提示按三类分别问“原画、规则设计还是实战体验？”“用它说说你喜欢怎么玩”“它在你的牌组里妙在哪？”；选牌弹层换一格就从头搜索，同一格误关再打开仍保留上次结果。草稿在选牌、离开输入框和离开页面时自动存到本机；底部只有两个按钮，“生成分享名片”成功后原位变成“发给牌友”，“生成名片图片”生成后原位变成“保存到相册”，完整卡牌与只看卡画是图片标题旁的两个文字选项。分享过的名片可以在页面最下面“撤回分享链接”，点了先弹窗确认，牌友手里的旧链接随之打不开。选好三张牌即可生成图片或分享；填写的文字通过审核后分享，朋友打开能看到这三张牌和短评，不做逐项对照（万智牌太多，很难选到同一张），作者可撤回。
- **禁牌表**：2026-09-09 核对的 Commander 官方快照、类别限制与 Lutri 的行侣限定状态；本机表态与真实社区票数分开。列表直接显示 43 张卡图，不逐张重复“禁用”，只标出 Lutri 的行侣限定；点选项即投票，改选直接点另一项，投过的可以撤票；表态比例排除“不了解”。投票只选立场，不区分休闲或竞技玩家，也不收补充理由，票数只看全部参与者。
- **对局约定**：强度目标、代牌、新系列预览牌、鸡飞牌（Un 系列搞笑牌）、无限组合技、额外回合、预计时长；新桌默认允许代牌、无限组合技和额外回合，预览牌和鸡飞牌默认聊完再定（旧约定和旧版小程序发来的约定没有这两项，也按聊完再定），玩家自行调整。改选项自动存本机；分享后同一个按钮变成“发给牌友”，回到页面时自动刷新确认人数；支持复制约定和另存一桌，约定变化后开启新版本，确认人数归零。
- **调牌记录**：选好换入与换出即可记录，也可记录同牌不同版本的替换；备注和套牌关联选填。默认随时复盘，关联战绩套牌后可设 3/5/10 场提醒；可保留、换回或继续测试。
- **这手留不留**：十手来自公开讨论的真实起手，Play to Win 播客的起手测试 8 手、Matt Sperling 在 TopDeck.gg 的调度文章 2 手。每手列出主将、座次、调度阶段与对手；七张牌沿用套牌试玩手牌区的卡图瓦片（66 × 92 横排、同样大小，放不下时横向滑动），点一张用系统大图预览。卡图直链由 `scripts/build-hand-card-index.js` 生成、随包提供，打开页面不发卡图请求。点“保留”“调度”或“还没想好”即投出一票，并显示来源的留牌或调度判断、按回合写出的理由和可复制的来源链接；投过票才显示社区比例，改选直接点另一个选项。服务端还没收录的题目只是不显示票数，不弹错误提示。不用自拟标题；牌张于 2026-09-14 按 Scryfall 核对 Commander 合法性，测试挡住当前禁牌表里的牌。判断是来源的看法，社区票数单独显示。

1. **首页** `pages/index`
   单屏酸性**粗野主义**索引：满版 `#D0F03C`，不使用渐变、纹理、玻璃或图片，不加载粒子组件或连接动画。全页色板为荧光黄绿 + 纯黑 `#0A0A0A` + 纯白 `#FFFFFF` + 一枚「事故色」电光蓝 `#00B3FF` + 半透明黑双档（`rgba(0,0,0,0.35)` 装饰 / `rgba(0,0,0,0.7)` 功能文本）；**唯一的例外是八枚入口序号的主题色**，集中收在 `.home-index-*` 八条规则里，测试会把它们剔除后仍校验其余部分只用那六个字面量，不许散到别处，无任何投影与渐变；圆角全页仅右上角那枚外跳入口一处（见下），其余一律直角。**整页 Voronoi 背景线场**：满页铺一层由发丝黑直线段构成的 Voronoi 胞元图，压在注释墙、字标与八行目录之下作底纹（`opacity: 0.45` × `rgba(0,0,0,0.35)`，实际比注释墙文字更淡，恒在所有内容之后）。选 Voronoi 是被约束推出来的——首页禁圆角、禁渐变、禁背景图、禁裁切路径，能用的只剩「直线段 + transform + 既有色板」，而 Voronoi 的胞元边恰好全是直线段，且作为 Delaunay 剖分的对偶天然不规则、不存在可重复的单元。几何在**构建期**由 `scripts/build-home-voronoi.js` 算好（泊松盘蓝噪声撒 34 个种子，避免纯随机的结块与空洞；半平面裁剪求胞元；固定随机种子保证可复现），落到 `config/home-voronoi.js`，运行时只推一次静态数据（78 段 / 3.5KB）；贴裁剪框的那圈边被丢弃，因此图形从四面被裁开，读作「更大结构的一角」而不是一个封闭的盒子。不画结点，只有线。**胞元必须闭合**，真机上看到的交汇处空缺全出在这里，两道收尾处理各治一个成因：① 顶点先吸附到 0.01vw 网格再去重——相邻两个胞元各算一遍同一条边，浮点尾数不同，不吸附就去重失败、端点错开；② 端头按夹角补长——线段是 1px 厚的矩形、端头是平的，两条矩形在夹角 θ 处相接时外侧会露出一块楔形，深度约 `(w/2)/tan(θ/2)`，夹角越小缺口越深，所以只有*有些*交汇处看着是空的；每个端头按它自己那个顶点的最小夹角补（当前最大 0.23vw ≈ 0.9px），钝角顶点几乎不补，不会在顶点上糊出一个点。**不要按「太短就是碎屑」丢边**——Voronoi 的短边是真实的胞元分界，丢掉就留下 2 度顶点，那正是空缺的样子。生成器每次运行都自检可见区顶点度数（必须全为 3）并打印 ASCII 预览。**坐标单位统一是 `vw`**（`left` / `top` / `width` 同单位），这是整页铺开后几何不变形的唯一依赖：改用百分比会让横向按容器宽、纵向按容器高分别解析，容器一旦不是正方形（整页容器天然不是）线段就落不到该落的端点上，胞元会在交汇处裂开。构建期画布 `100 × 240 vw`，覆盖到 2.4 的屏幕长宽比，覆盖宽高比不超过 2.4 的屏幕，超出时需检查背景边缘；四周另留 26vw 外扩，旋转扫到边角时不露白。**动效不走 setData**：两层嵌套容器各挂一条纯 CSS `transform` 动画，不需要每帧 `setData` 重算几何；实际合成与绘制成本取决于渲染器、元素数量和设备。主运动是内层的 `home-field-drift`：一条**不规则闭合回路**，六个关键帧、时间间距不等（14/15/18/14/22/17），周长 32.1vw，`53s linear infinite`，约 0.6vw/s——在 390 宽的机型上 2.4px/s、十秒走 24px，看得出在动又不抢注意力；段速在 0.41–0.79vw/s 之间差近两倍，所以不会读成匀速转圈。**主运动不能用 `alternate`，也不能用缓动**：往返式动画在两端速度归零，而开屏那一刻正好停在起点，用户最可能盯着看的头十几秒恰恰是最慢的一段——初版就是这么「真机上看着没动」的（71s `ease-in-out` ±2.4°，开屏 15 秒内页面中心只移动约 0.7px，肉眼根本读不出来）。外层 `home-field-turn` 是次要的差分运动，绕整页中心 `alternate` 慢转 ±2.4°（实际周期 142s），让上下不是整块平移的死板感；它与 drift 的 53s 互质，合成轨迹约 2.1 小时才回到同一相位。两层位移合计不超过 11vw，远小于构建期留的 26vw 外扩量，旋转扫到边角不露白。两层都加 `will-change: transform` 提示合成器提层，提示渲染器优化变换，是否独立合成仍需设备测量。系统开启「减弱动态效果」时两层动画一并停止；整块 `aria-hidden` + `pointer-events: none`，不进无障碍树也不吃触摸。上方 45vh 是整墙工业注释：九句全大写英文规则宣言（EDH 规则、cEDH 竞技与社交默契各成段落），7px Courier 半透明黑、行距极密、整块轻微逆时针倾斜 1.3°，其中一整行被「审查涂黑」——每次进页随机选一行（`onShow` 掷 `redactionLine`），给该行挂 `is-redacted` 把它自己的文字盒染成实心黑、字色同底而隐去，左右各外扩 6rpx 作马克笔涂抹感。黑条即文字盒本身，因此与文字天然等宽等高、必定盖住，不做任何像素定位（字体回退与屏高断点都不会让它悬空），像被临时涂黑的一条规则，营造满墙涂鸦式信息过载（每句 ≤46 字符，测试检查字数；窄屏及放大字体仍须检查），只用字母数字与空格。hero 底部锚定被横向拉伸变形（`scaleX(1.18)` + `skewX(-10deg)`）的超粗纯白 `cEDH Tutor`（内嵌 Archivo Black，48px，字号留边以保证品牌名在窄机型不被右缘裁切，窄屏 / 矮屏 42px、600px 以下 38px）与点阵「竞技指挥官导师」，与下方点阵目录形成「喊叫 vs 低语」的字体对比。下方 55vh 是八行目录，刻意打破常规排版：行高不等（tall/short 用不同 `flex-grow`）、火花觉醒与混沌工具两行整体右移打破左对齐线、**01–08 序号是填满整行上下的超宽斜体底版，且只在随机 glitch 到的那一行出现**。Archivo Black 横向拉到 `scaleX(1.9)` 再斜 `skewX(-10deg)`，竖直居中、绝对定位、左缘与中文对齐，上下两端都被行框裁掉一点——数字不是拿来读的，是这一行的底版。**常态完全透明，只有 `.is-glitch` 那一行把它显示出来**：八行同时铺满巨号会跟整页线场糊成一团，而每次进页只亮一行，它就从墙纸变成了一次事件。**同屏因此永远只有一个数字，「八色两两分得开」这条判据随之作废**（没机会并排比较），原来那条按酸性黄绿算混合 ΔE 的门禁一并撤掉；留下的判据只有「压在底版上的黑字还读不读得了」，而且按 glitch 行真实的电光蓝底算。**glitch 行用 `opacity: 0.28` 而不是常态那套 0.38**：电光蓝比酸性黄绿暗得多（相对亮度 0.37 对 0.78），再叠一层暗色就没余量——实测 0.38 时三行的黑字掉到 4.5:1 以下（最差 3.91:1）。0.28 是窗口中点：最差黑字 4.84:1 过 AA，最差可见度 1.27:1 仍看得出来。两头都有门禁卡着。**数字保留本行主题色、不跟着 glitch 转黑**：整行反相成蓝底黑字，只有底版还留着这一行自己的颜色，读作「故障之下这一行的本色透出来」——也因此那八条 `.home-index-*` 不会变成死代码。**斜化走 `skewX` 不走 `font-style`**：这款字没有斜体字面，写 `italic` 系统只能合成，而合成本身就是切变——不如显式写出角度、拿到确定的结果；字标用的也是 `skewX(-10deg)`，两者因此是同一个动作。首页仍**全页零 `font-style: italic`**。**`skewX` 必须排在 `scaleX` 左边**（即后作用于已拉宽的字形），视觉倾角才是标称的 10°；排到右边先斜后拉，1.9 倍会把倾角放大到约 18.5°，跟字标就对不上了。**字面沿用字标那一款并沿用它的变形手法**：包里没有第三款字，`scaleX` 与 `skewX` 都是这一页已经在用的（字标是 `scaleX(1.18) skewX(-10deg)`），底版拉得更远是同一个动作推到更远。首页因此仍只有两种声音：Archivo Black 喊（字标 + 序号底版），点阵字低语（中文 + 副标题）。**拉伸必须绕左端不能绕中轴**（`transform-origin: left center`，与字标一致）：填满行高之后数字本身就很宽，绕中轴拉会把左半边推到 `left: 0` 之外，而行的 `overflow` 在 padding box 裁切，那里会切出一条硬邦邦的竖边。**字号按行高分三档，比例直接取自已有的 `flex-grow`**（tall 1.45 / base 1 / short 0.72 → 14.5vh / 10vh / 7.2vh），所以「每一行的数字填满自己那一行」是同一条规则，不是八个各自拍脑袋的数值；测试按 `flex-grow` 等比反推这三个字号，改了行高比例而忘了改字号会立刻红。**字号必须用 `vh` 不能用 `px`**：八行是 `.home-actions`（`flex: 1 1 55%`）按 `flex-grow` 分的，高度跟着视口高走。**`display: block` 是显式写的**，不靠 `position: absolute` 去隐式块化：WXML 的 `<text>` 是行内组件，这一条不能省。**不写 `font-weight`**：这款字本身就是 Black 字重，而 `wx.loadFontFace` 注册时不带字重描述符（即注册成 `normal`），写 `900` 系统只能合成假粗体、把本来就厚的笔画抹糊。八行的主题色仍与 `config/particle.js` 的 `palettes` 同源、互不重复——人格测试品红、火花觉醒橙棕、强度分级翡翠、套牌试玩长春花蓝、血量记录深绯、混沌工具紫罗兰、我的主将橄榄、环境梯度朱砂；「分色按 CIE Lab ΔE 量而不按色相角」那条仍在（初版 `#C61A28` 与 `#C71807` 色相差 12° 但 ΔE 只有 14.7，肉眼就是同一枚红；现全局最接近的一对为 39.4）。基类刻意**不设 `color`**——颜色只能来自八条按行规则，漏挂一行会直接继承成黑色而露馅，测试专门锁这条。**反相态靠选择器权重压过按行主题色**：glitch 行是电光蓝底、按压态是纯黑底，八种主题色在这两种底上都会糊掉，`.home-button.is-glitch .home-button-index`（三类）与 `.home-index-active .home-button-index`（两类）都重于单类的主题色规则，因此不必逐色写反相；这两条不能被改回单类选择器。序号仍以 `min-width` 等宽成列，中文左缘才对得齐——更早的版本各行 84–108rpx 不等，反倒把各行的中文推到了不同起点，那种参差本身就是「乱」的一部分。这块前后改过七轮（四种字面声音按行的角色分配 → 网格整数倍保证锐利）与右对齐英文副标题之间只以留白区隔（space-between）；按「认识偏好 → 构筑验证 → 桌面对局 → 记录复盘」排列：人格测试、火花觉醒、强度分级、套牌试玩、血量记录、混沌工具、我的主将、环境梯度，英文副标题依次为 `EDHTI PROFILE`、`COMMANDER FINDER`、`BRACKET ANALYSIS`、`DECK SANDBOX`、`LIFE COUNTER`、`CHAOS TOOLKIT`、`COMMANDER LOG`、`META TIER LIST`。**事故色 glitch**：每次进入首页随机让其中一行「故障」成电光蓝底黑字（`glitchIndex` 在 `onShow` 重掷，八行皆可命中），打破纯黄+黑的安全感。**暴力按压**：按下整行在 60ms 内反相为纯黑底 + 电光蓝字，不弹跳、不缩放。cEDH 精神题词 7. **血量记录** `pages/life-tracker`
   横屏分区血量计，支持 **2 / 3 / 4 / 5 人**四种模式：两人上下对坐（上位反转）、三人上一下二（第一位横跨整行且反转）、四人十字四分、**五人两两对坐 + 一人坐右短边**（左侧仍是四宫格，右边留一条 20vw 竖栏）；分隔线随模式增减（两人无竖线、三人竖线只画下半、五人横线只画到竖栏为止且竖线与中心菜单一并落到四宫格中缝）。五人局的三个坑：① 五个座位必须**全部**显式 `grid-area`，只给 seat-5 指位置的话自动流会把 seat-3 塞进右上角、四宫格当场散架；② 侧坐不能整块 `.player-face` 转 90°——盒子还是竖栏那个瘦长尺寸，转完视觉宽高对调必然溢出；改成加减区用左右两列（对他就是上下）、只把数字那一块转 **-90°**（他坐右边朝屏幕左侧看，他的「上」是屏幕负 x 方向，转 +90° 对他是倒的）；③ 座位朝向从页面里硬算改成查 `config` 的 `seatFacing` 表——「前 N 位坐上边」表达不了侧坐，而且这张表同时被边缘赛跑用来决定光跑过哪条边，两处各算一套迟早对不上。标准 Commander 的 2 / 3 / 4 / 5 人模式均从 40 点开始；人数不能自动代表 Duel Commander（切换人数即按新默认重开，重置同理）；点击 / 长按快速增减并限制在 -999～999。中心 RGB 椭圆菜单提供返回主页、重置对局与人数切换（当前档高亮；切换按新人数重开对局并按序保留座位名）；触发胶囊视觉仍为 36×28rpx，但可点热区扩至 88rpx 见方，菜单胶囊 44rpx 高、16rpx 字号；进入页面时请求系统常亮，退出时恢复默认熄屏，并用版本化本地存储尽可能恢复当前对局（旧版四人存档无 `playerCount` 字段仍自动兼容）。**重置与切人数给撤销而不是二次确认**：这两条会抹掉一整局血量，但在长局里都是高频合法操作，加确认框等于给正常路径多加一次点击；因此它们先用 `cloneLifeState` 留一份快照，再在**屏幕顶部居中**显示 8 秒的可点撤销条（撤销按钮热区 88rpx）。贴顶而非贴着中心菜单，是因为本页锁横屏：`rpx` 由「宽」推导，横屏下宽是长边，`50vh + 150rpx` 这类混算约等于 349pt、加上条高会溢出 375pt 的视口；且中心菜单向下展开、横屏下已到约 91vh，下方没有空间。**横屏页做纵向定位不要混用 `vh` 与 `rpx`。**，一旦有人继续记血或页面隐藏/卸载即收起。

   **中心菜单的纵向预算是硬约束，只有两行**：菜单从 `50vh` 往下展开，高度却全是 `rpx`——而 `rpx` 按**宽**推导，横屏下宽是长边，于是屏幕比例越大，同样的 `rpx` 高度吃掉的 `vh` 越多。实测底边位置：两行在 1.78:1 上是 83.7vh、2.16:1 上 91.0vh、2.28:1 上 93.2vh（都安全）；**三行在 2.16:1 上直接落到 105.4vh，整行在屏幕外**。所以新增动作一律并进已有的行，不要往下堆——「抽先手」因此与主页、重置同在第一行（第一行＝按一下就发生一次的动作，第二行＝按住不变的人数档位），而不是自己占一行。`life-tracker.suite.js` 有门禁按真实常量算这件事：从 WXSS 解析 `top` / `height` / `gap` / `width`，从 WXML 数行数与每行按钮数，在 2.3:1 上算出底边必须 ≤96vh，同时校验每行按钮均分后放得下最长的那个标签。加一行、改行高、改顶部偏移、收窄菜单，任何一项越界都会立刻红，不用等真机。

   **随机先手（边缘赛跑）**：菜单里「抽先手」触发——一道光沿屏幕外缘按围坐顺序跑过每个人的座位边，减速，停在中签者那一段，之后那条边留成他的颜色，整局都在。**全程不出文字**：一半座位转了 180°，任何一句「你先手」对另一半都是倒的，而边缘指示不依赖文字方向。**先由 `rng` 抽出先手，再倒推动画要跑多少步**——反过来做（先定步数、看落在谁头上）会让概率依赖 `laps` / `easing` 这些节奏参数，改一下节奏就悄悄改了公平性，而且没法测；抽签复用等大小整数桶与尾部重抽；在随机源均匀、独立的假设下，各座位等机会。实际 `Math.random` 只要求近似均匀，频数测试不能证明设备随机源的公平性；动画只展示已抽出的结果。围坐顺序单独存在 `config` 的 `seatRing` 里，因为 **DOM 顺序不等于围坐顺序**（三人局顺时针是 1→3→2，四人局是 1→2→4→3），拿 DOM 顺序跑光会在对角之间乱跳。**彗尾而不是单格闪烁**：头部之外再亮两格递减，既读得出光往哪边跑，比单格闪烁更容易辨认方向；动效使用 3rpx 边线与不透明度变化。本轮未作 WCAG 闪烁阈值的设备测量，不将细线或彗尾当作已通过该项验收的证明。过渡 140ms 比最快那一档 55ms 还长，所以快段来不及亮到满——「转得快时发虚、慢下来才逐渐结实」是自然长出来的，没有另写一套。**高频那几帧只走定向路径 `setData`**（`players[i].raceLevel`），整个 `players` 数组每 55ms 全量过桥是这一页最贵的写法；`life-tracker.suite.js` 真驱动一遍页面对象来验这条，光看源码看不出来。切后台 / 重置 / 切人数 / 离开页面都要掐掉正在跑的序列，否则它会在新的一局里凭空点亮一个座位。

8. **套牌试玩** `pages/playtest`
   粘贴 MTGO / MTGGoldfish / Moxfield 纯文本牌表本机开局。支持 `Commander / Deck / Mainboard` 区段标题或空行分隔指挥官。六区（牌库/手牌/战场/统帅区/坟场/放逐），抓牌、打出、拖放、横置、Token、长按手牌/战场卡放大查看卡图（战场卡自定义拖拽会打断系统长按，用计时器兜底稳定触发）、长按牌库查找（带搜索框，40 张一页按需加载，选牌后自动洗牌关库；内含 **展示库顶** 开关，开启后牌库按钮以库顶卡 `art_crop` 无字大画铺底，服务 Bolas's Citadel / Mystic Forge 类「可见并从牌库顶施放」效应，随抓牌/洗牌实时跟随、新开局自动回隐藏）。**战场指示物**：战场卡右上角显示指示物计数角标（`pointer-events:none` 纯展示层，不截获卡面的单击横置/拖拽/长按），数量在长按详视弹窗内以 `[−] N [+]` 步进器（64rpx 触控）增减；夹在 0–999，归零即隐藏角标、删字段。指示物只属于战场卡（token 长按是删除，走不到详视故不支持），离开战场随卡对象重建而丢失（符合规则）；`counters` 以 `{类型:数量}` 存、当前只暴露通用一类，随对局版本化持久化。**区域芯片卡图**：统帅区按结算页方式呈现主将卡图（单主将居中、双拍档左右分屏），坟场/放逐区恒显最上方一张（最近置入）的 `art_crop` 大画。非牌库区卡面使用 `small` 尺寸 Scryfall 卡图，Token 离场即消失；收到系统内存告警后自动撤下非必要卡图并保留文字操作。导入限制为 50,000 字符、250 张总牌与最多 3 张主将，避免异常数量展开占满内存。**战场下方横向五色+无色法术力栏**（各色手动整数计数 0–99，是工具范围，不是游戏的法术力上限）（WUBRG 惯例横排、回收战场满宽，零值时半透明；+/- 增减，牌表与法术力池均经版本化存储持久化）。右上角按钮：撤销（有上一步时显示）/ Token / 刷新 / 随机弃（手牌非空时显示，确认后随机弃一张至坟场）/ 重置。**一步撤销**：抓牌、打出、横置、拖放、收回手牌、随机弃与面板移动都先经 `captureUndo(label)` 用 `utils/playtest.js` 的 `cloneGame` 留一份六区快照（`counters` 是唯一嵌套字段，单独浅拷贝以与现局面完全脱钩），撤销即把快照装回去；只保留一步、不引入历史栈，新开局与已确认的「刷新」都会清掉快照。导入页顶部与强度分级是同一张说明卡，右上角「粘贴」从剪贴板导入；「清除现套牌」是少用操作，放在底部居中的次要文字，点了仍先确认。导入态页面锁定一屏高（`.playtest.is-input`），输入框和强度分级一样用可压缩的 `flex: 1 1 0` + `min-height: 0` 填满剩余高度，下面的按钮与版权说明不会被裁出屏幕。

9. **环境梯度 / Meta Tier List** `pages/meta`
   收录 **cEDH小屋**（`BY CPP123 + 345` 里的 345，即本项目合作方）人工编辑的 cEDH 套牌梯度表，**经作者授权**。按 T0–T4 分档列出 56 个原型，每条含中英名、指挥官、标签，点开看概述 / 制胜路线 / 优势 / 劣势 / 详细评价。指挥官卡图按 `scryfall_id` 直连 Scryfall（比 `?fuzzy=` 名字匹配精确，不受中英卡名与印次歧义影响）；参考牌表是 topdeck.gg 外链，个人主体不能用 `web-view`，因此**只复制到剪贴板**，与推荐结果页同一做法。

   **快照而非实时**：数据随小程序包发布，不联网拉取——本项目不引入 Scryfall 之外的第二个请求域名。梯度更新流程是「覆盖 `tools/meta-tier/current.json` → 跑 `node scripts/build-meta-tier.js` → 重新提审」。页面顶部常驻发布日期。

   **每周自动巡检**：`.github/workflows/meta-tier-watch.yml` 每周一 05:23 UTC 拉一次上游 `current.json`（也支持手动触发），有变化就重新生成配置、跑 `npm run check`，然后**开 PR 而不是直接推 main**。两条理由：其一快照必须重新提审才会到用户手上，自动提交并不等于上线；其二上游一变就可能触发本地门禁——最常见是新增了很长的双拍档名而 `COMMANDER_SHORT_NAMES` 没收录，导致列表行宽度断言失败，那正是需要人补一条短名的信号，不该自动绕过，所以**门禁失败时照样开 PR**，把原因写进正文。比对逻辑在 `scripts/meta-tier-diff.js`：比的是规范化后的 JSON 而非原始字节（仓库文件可能是 CRLF、上游是 LF，逐字节比会每周误报一次「有更新」），并会拦下上游返回 HTML 错误页的情况。

   **导入时强制过滤**（`scripts/build-meta-tier.js`，测试逐条守住）：只收 `status === 'reviewed'` 且未下架、且档位在已声明列表内的条目——上游 `unranked` 是编辑区，绝不能公开；剥掉 QQ 群号一类站外导流（提审敏感），但**署名与免责声明必须保留**，那是随数据走的义务；丢掉本地图片路径等运行时用不到的字段。

   **列表与详情走两条投影**：`setData` 是小程序唯一的跨线程通道，推过去的每个字节都要序列化。列表用 `toListItem` 只带真正渲染的字段（名称、字号档位、标签、`art_crop`），详情走 `findEntry(id)` 从 `metaTierEntries` 重新取完整条目。此前列表直接推完整派生结果，56 行 67KB，其中 34.7KB 是列表一个字都不渲染的 `summary` / `analysis` / `commanders`——而详情本来就重新取，那份副本从没被读过。拆开后首帧 **67.2KB → 23.5KB**。测试守住三件事：列表项不得携带详情字段、列表卡图不得携带 `normal` / `cn`、总量不超过 40KB。

   **字面分工**：档位标签用首页那套内嵌点阵字体（`HomePixel`），页面其余部分保持等宽——「点阵＝排名刻度、等宽＝元信息」。选点阵不是为了呼应首页好看，而是点阵网格本身就是「一格一格排下来」的分层形态，与榜单内容同构。字号必须用 `px` 且落在 10px 网格整数倍上（当前 20px），用 `rpx` 会随屏宽缩放、破坏点阵网格。字体是页级注册（`global: false`），首页那次注册在本页无效，`meta.js` 必须自己再注册一次；包内已有该字体，重复注册不产生额外下载，失败则回退等宽栈。

   **与强度分级刻意解耦**：梯度是署名的人工判断，强度分级是本地确定性规则 + 可审计判定链。把前者注入后者会毁掉判定链的可审计性，也会让同一副牌的档位随第三方编辑改动而变。因此评估器侧禁止 `require` 梯度数据（有测试守），B5 也**不再承诺**「待 meta 分析加入后提供」。页面署名写明「不代表本工具的强度分级结论」。

## 技术约束

- 原生 WXML / WXSS / JS；默认竖屏，血量记录页单独横屏；个人主体，不用 `web-view`。
- 指挥官 / 问卷 / Bracket 规则 / 贴纸 / EDHTI / 血量 / 卷心菜 / 伊捷 / 粒子 / 性能阈值全是本地配置（`config/`）。
- **标题字体**：首页中文与入口使用 Fusion Pixel Font 10px Monospaced `zh_hans` 2026.07.01 的受控子集，包含主页所需中文、ASCII 与数字（顶部注释与底部 imprint 使用 Courier 等宽栈），测试逐字核对首页 WXML 的静态文字都在子集里；`assets/home-pixel-font.js` 内嵌约 15KB TTF 并注册为 `HomePixel`。`cEDH Tutor` 单独使用 `assets/title-font.js` 内嵌的 Archivo Black WOFF2，注册为 `cEDHDisplay`，并以系统粗体栈兜底。两种字体均由 `pages/index/index.js` 本地加载，失败时直接显示回退字体，不遮挡首帧。Fusion Pixel 完整 OFL 随发布包放在 `assets/FUSION_PIXEL_OFL.txt`，源子集、授权副本与再生成脚本分别位于 `tools/fonts/`、`scripts/build-home-pixel-font.js`；Archivo 也继续供 EDHTI 导出海报与血量数字使用。
- **两卡组合技识别：Commander Spellbook 快照**（`config/spellbook-combos.js` + `utils/spellbook-combos.js`）。当前快照收录 3,086 组配对，涉及 1,853 张牌；包括产出无限循环或标签映射至四档的双卡配方，排除禁牌标签。手工库保留中文描述与家族归并，配对标签由快照提供。映射 `R=4 S=3 P=3 O=2 C=2 E=1` 是本工具对社区定性标签的简化；本工具对这类命中采用至少 B3 的保守内容基线，不能据此断言所有配方都是官方认定的真正双卡组合技。完整条件仍应查原配方。记录按牌名配对去重，优先保留较高映射；同家族证据合并，正文至多举两组，每组带自己的产出分类；长牌名时减少举例，保留完整名称与启动条件说明。双面牌支持全名与正面名两种匹配形式，使用同一 `canonicalCardKey`。运行 `node scripts/build-spellbook-combos.js` 同步后，检查新快照、完整条件和回归结果，再上传开发版。
- **卡图直链三级取**（`utils/card-art.js`）：① **构建期烤表** `config/commander-art.js` —— 本地 100 位主将是固定不变的一份表，推荐结果、EDHTI 无字大画、强度分级 hero 底图、战绩头像都只从这里取名字，所以直链在构建期就算好烤进包里，这四条链路**不发卡名解析 API 请求**，卡图仍从 CDN 加载，卡图地址从首帧起确定，图片下载期间仍显示占位。② **上次会话落的盘**（`cardArtIndex`，30 天保质期）—— 缓存有效时，同一副牌再次打开无需解析卡名；CDN 图片是否重下由实际缓存状态决定；烤表内容不重复落盘，写入推迟一跳避开首屏那次 `setData`。③ **本次批量解析** `/cards/collection`，75 张一批。三级都没有才由调用方回落到 `?fuzzy=` + `format=image` 的 302 慢路。存储与烤表里的地址压成 `<scryfallId, 版本时间戳>`（判据在 `utils/scryfall-cdn.js`），但那是**拿到真地址后逐档比对过**才压的，跟「凭卡名瞎猜路径」是两回事；比对不上的原样存字面量。改了 `config/commanders.js` 要重跑 `node scripts/build-commander-art.js`，`card-art.suite.js` 有门禁守着漏烤。
- **批量查牌以正面名构造标识符**：2026-10-06 对 Agadeem’s Awakening、Wear 和 Brazen Borrower 的实测中，`/cards/collection` 未找到完整 `A // B` 名，使用正面名均命中，响应保留完整多部分名称。导出牌表可能采用全名；卡图与强度分级共用 `utils/scryfall.js` 的 `collectionIdentifier`，请求正面名并保留完整名用于别名匹配。请求未命中时，卡图可以回落到 named 图片端点，强度分级则将该牌记录为元数据未覆盖；两条链路的后果不同。named 与 collection 的匹配行为不能互相推定，也不将本次样本写成所有牌张的永久保证。
- **一次请求能同时喂两个用途就别发两次**：强度分级读牌表时本来就要为整副牌打一趟 `/cards/collection` 拿 `cmc` / 类别 / 价格，那份响应里带着 `image_uris`；`bracket-metadata.js` 顺手调 `rememberCardArt` 收进卡图缓存，hero 底图因此是白得的。
- **首屏要的排最前，每批回来就刷一次视图**：`prefetchCardArt(names, { onBatch })` 按调用方给的顺序分批。试玩页把「屏幕上真会显示的那几张」（手牌 + 战场 + 统帅区）排在最前，百张牌仍是两批、请求数不变，但第一批一回来七张手牌就有图了，不必等第二批。中途刷视图时 `artReady` 仍是 `false`，没解析到的返回空串只显示占位底——**绝不能在这时放开回落**，否则后一批一到就要把已显示的图换掉重下一遍。
- **Scryfall 元数据**：`utils/scryfall.js` 的 `normalizeCardName` 把弯引号（Moxfield 导出）归一化为直引号，并把撇号编码为 `%27`（裸撇号会让微信 `<image>` 加载失败）。JSON 卡图请求设 8 秒超时、全局最多 4 个并发请求，并校验 HTTP 状态与响应结构；同卡并发请求复用 Promise，成功缓存上限 64 项，失败会清缓存以允许重试。`utils/bracket-metadata.js` 通过 `/cards/collection` 以 75 张为上限顺序分批读取 `cmc`、正面 `type_line`、`oracle_id` 与 `prices.usd`；只对超时、请求失败、408、429 和 5xx 做一次受控重试。当前印次没有非闪 USD 时，以多个 Oracle ID 合并搜索其他纸牌非闪印次；成功、明确未找到和本轮无价结果会话内去重，网络失败仍允许下次重试。
- **本地存储**：页面不直接读写 `wx.*StorageSync`，统一经 `utils/storage.js`。当前键：`quizResult` / `quizDraft`（问卷结果与在答草稿）、`edhtiState`（EDHTI 进度与完成态）、`bracketDeckText` / `playtestDeckText`（两页各自的牌表）、战绩、血量、法术力池与贴纸。**长流程一律可中断可恢复**：多步问卷与需要粘贴长文本的页面都必须落盘，中途切后台不该让用户白干。新数据保存为 `{ schemaVersion, updatedAt, data }` envelope；历史裸值自动升级，损坏数据安全回退，未来版本数据禁止被旧版覆盖。写入/删除失败返回显式结果，由页面提示用户而非静默丢数据。
- **设计 token 必须先定义再使用**：`var(--x)` 取不到值不会报错，只会悄悄回退成继承值——字号、间距、颜色都会静默失真，Node 测试和真机都看不出「本该是多少」。`--cedh-text-11` 曾被随机工具与环境梯度用了却从未定义。`shared.suite.js` 有全项目门禁扫描未定义的 `--cedh-*`。
- **异步 wx API 一律显式传回调**：微信的异步 API 无参调用（`wx.hideKeyboard()`、`wx.hideLoading()`）会返回 Promise，拒绝时没人 catch 就冒成框架级的 `Error: timeout`——栈里全是 `WAServiceMainContext`、没有任何应用帧，极难定位。典型触发：用「粘贴」按钮填入牌表时键盘从未升起，`hideKeyboard` 无键盘可收即拒绝。`shared.suite.js` 有全项目门禁扫描无参异步调用（同步 API 如 `getWindowInfo` 在白名单内）。
- **异步一致性**：推荐结果页用「主将 + 分数 + 契合度」签名识别当前结果；强度分级用递增请求编号识别当前牌表。旧 Scryfall 请求即使延迟返回，也不会写入新一轮问卷卡位或已修改的牌表。
- **分享**：全部页面声明 `onShareAppMessage` / `onShareTimeline`，经 `utils/share.js` 调 `wx.showShareMenu`。

## 稳定性边界

- 核心推荐、Bracket 解析与分级、牌区状态机、战绩统计、计数器和法术力池均放在可由 Node 直接测试的纯逻辑模块中；页面层负责微信生命周期、渲染和用户反馈。
- 首页不挂载粒子组件；各粒子页面以 `palette` 属性使用与页面主题一致的点、线配色，并随帧率自动降档，收到系统内存告警后固定使用低档并缩减粒子池，页面隐藏或组件卸载时停止动画并释放画布引用。
- 本地数据仅保存在当前微信设备，没有云同步；清理微信数据或换机前应先使用功能内已有的导出能力保存重要记录。
- Scryfall 不可用时，推荐与本地工具仍可运行；强度分级回退到本地规则且明确显示 0% 元数据覆盖，卡图区域保留预填直连地址或结束 loading，不会阻塞主流程。
- Node 测试不能替代微信运行时验证。提审前仍需在开发者工具和至少一台真机检查触摸/拖拽、相册授权、Canvas 导出、弱网卡图和前后台切换。

## 上线合规

- **相册保存**：后台隐私指引中的声明与发布、微信隐私授权、`scope.writePhotosAlbum` 和设备权限分别核查；仅有后台声明不能证明线上已保存成功。EDHTI 与玩家名片均应从首次安装、拒绝授权、允许授权和重新进入四种情形验收，并以 `wx.saveImageToPhotosAlbum` 的成功回调及实际相册文件确认结果。当前代码证据不替代真机验收，保存失败也不能未经检查就归因于隐私指引。

  - `cards.scryfall.io` 现在是卡图的**主路径而不是重定向目标**——卡图已全部改为直连 CDN，少配这一条会让画布导出取不到图。
  - `api.scryfall.com` 在 downloadFile 里仍要保留：批量解析失败时按卡名取图的回落路径仍走它（`?format=image` 会 302 到 CDN）。

- **AppID**：使用根目录 `project.config.json` 中实际小程序的 AppID。配置文件不能证明主体资质、操作账号权限或提审资格；这些以小程序后台当前状态为准。

## 视觉规则

- **网络图三件套**：凡是 `src` 绑定数据的 `<image>`，都必须 ① 有占位底色（`--cedh-image-placeholder`；深色页用自己的深底）② 挂 `lazy-load` ③ 高度确定。前两项由 `shared.suite.js` 自动校验——这次审出 7 处缺占位底、1 处缺 `lazy-load`，靠人工记显然记不住。**第三项没做成门禁**：判定它要理解完整祖先链（强度分级的 hero 底图是「图 `height:100%` → 父 `.hero-art-split` 也 `height:100%` → 祖父 `.hero-art` 才是 `position:absolute`」），静态正则解析 WXML 嵌套不可靠，初版把这三处正确代码误报成了违规。主包既有网络图已人工逐个核过：高度全部确定或本就脱离文档流，无布局抖动；新增图片时请自行确认。
- **图片档位按格子形状选，不跟详情页共用同一张**（[Scryfall 官方规格](https://scryfall.com/docs/api/images)）：JPEG 的 `small` 是 146×204，`normal` 是 488×680；`art_crop` 尺寸随印次变化，不能统一按 626×457 计算，文件字节也因图片内容而异。双拍档列表每格为 66×96rpx，`small` 的长宽比接近容器，可减少不必要的大图加载；`aspectFill` 仍会裁边。在 390 CSS px、DPR 3 的例子中，目标约为 103×150 像素，其他设备按实际视口计算，不把像素面积比写成网络流量节省比例。单主将横格与战绩圆头像继续使用纯画作，避免整卡裁出类别行和规则文字；这属于内容呈现取舍，不承诺所有卡图零裁切或固定节省比例。

- 首页以 `#D0F03C`、`#FFFFFF`、`#0A0A0A`、事故色电光蓝 `#00B3FF` 加半透明黑双档为全部色板——`rgba(0,0,0,0.35)` 作装饰（注释、发丝分隔线、imprint、侧脊题词），`rgba(0,0,0,0.7)` 用于承载功能语义的英文副标题（过 AA 正文对比度），编号提为纯黑巨号（最大对比）；电光蓝是唯一的「事故色」，只用于随机 glitch 行底色与按压反相时的字色，其余一律保持黄+黑；全页不使用投影、渐变、纹理、玻璃与图片，首页不加载粒子或连接效果，全部文字无阴影；入口按压用专属 `home-index-active` 在 60ms 内反相为纯黑底 + 电光蓝字，不缩放、不位移。
- 除首页外的非导出页面禁用 `radial-gradient` 背景光斑，只保留线性底色 + 玻璃层 + 粒子背景 + 语义色。**唯一例外**：血量记录的玩家分区光晕（`life-tracker.wxss` 中由 `--player-rgb` 驱动、每位玩家一色，是该页核心视觉）。该例外由 `shared.suite.js` 的发布门禁锁定——它同时校验「除此之外没有第二处」以及「这处光晕必须由 `--player-rgb` 驱动」，避免例外被当成放行通用装饰光斑的口子。
- 导出图是独立海报视觉，可用渐变/纹理/暗角。
- **全局不用点号**：产品文案不用中点、圆点做分隔或项目符号，标题与数量之间用全角空格或斜线（试玩页区面板的标题与张数、名片海报的版本与语言）。官方中文牌名里的间隔号（诺曼·奥斯本）是牌名原文，保留。`shared.suite.js` 扫描 miniprogram 下的 WXML、WXSS 与 JS，先剥掉注释，只放行前后都是汉字的间隔号。
- 通用按钮按压反馈集中在 `app.wxss` 的 `pressable-active`；首页目录行不继承其位移反馈。
- **胶囊套胶囊要同心**：内层被外层包住时，上下内缩 `(外高 − 内高) / 2` 必须等于该侧的 `padding`，否则两个 999rpx 圆角不同心，真机上一眼就是「没对齐」。血量记录的撤销条是这条规则的实例（外 56rpx / 内 44rpx / 右 6rpx），`life-tracker.suite.js` 用算式而非字面量锁住它。
- **实心底色的文字块要自己补回间距**：给文字加 `background` + 横向 `padding` 后，色块会宽出字形，把原本靠字形侧边距形成的留白吃掉、直接顶到相邻文字。首页 02/06 的涂黑编号即为此显式加了 `margin-right`，且必须大于黑块外扩量（`ui.suite.js` 按此关系断言，不锁死具体数值）。
- 页面主题在 `styles/themes/`，卷心菜绿 `#2fa75d`、伊捷蓝 `#5aa9ff`、自伤/输红 `#e0655c`。
- **技术仪表语汇（dark-table 工具页：tracker/random/playtest/cabbage/izzet）**：关键数值是英雄——超大等宽 `tabular-nums` 数字（tracker 胜率、random 随机数/骰点、cabbage 现可造绿、izzet storm/瞬间/自伤、playtest 法术力与区计数），段标题与数值标签退为等宽大写 tracked「微标签」（`--cedh-font-mono`、`letter-spacing` 0.14–0.2em、`text-transform: uppercase`、模块 accent 色）。不使用装饰性刻线或短横。首页与导出海报保持各自语汇；result/quiz 是展示型页面不套用此语汇。

## 改动口径

不是代码风格，是「什么样的改动会被接受」。每条都由真实的返工得出，写下来是为了下次少走同一条弯路。

- **先整体删掉，再以最小形态加回。** 首页 01–08 序号连调四轮仍是「太乱了」，最后的处理不是继续调，而是**先全部删掉**——首页少了序号照样成立，这就证明它是可选装饰而非结构件；加回时只保留「与英文副标题同字体同字号、按入口主题色着色」这一个最小形态，比继续微调干净得多。同一逻辑也用在阴影（八行八种投影 → 全删）和 MTGso 外跳入口（四轮修不好 → 整个功能删除）上。**一个元素调三轮还没对，先怀疑它不该存在，而不是怀疑参数没调准。**
- **一次只动一个变量。** 「八行 × 八种字体 × 各自字重形变」的结果是「完全错乱」——同时动四个维度时，看不出是哪一维在制造混乱，也就无法收敛。明确锁死其余维度（「不要改变 0 与 # 的相对大小，只变字体」）之后，一眼就能判断「字体这一维到底够不够」。
- **差异只允许挂在一个维度上，其余维度必须完全一致。** 八个入口最终的差异载体只有主题色，字体、字号、字重、倾斜全部统一。并且承担差异的那一维必须真的分得开：1/5/8 三色在人眼上几乎同色，按 CIE Lab ΔE 重排后才成立——**暗色下色相角不可靠，判据要用感知色差而不是 HSL 数值。**
- **报症状，不开药方。** 「找出根本原因」「越改越慢，还不如最初版」「有时候图完全显示不出来」「真机上并没有动起来」——这几句都没指定怎么修，因此逼出的是结构性错误而不是补丁：双面牌的正面名永远命不中缓存（`card.name` 与 `card_faces` 拼出的名字是同一个串，正面名从未入表）、新导入的牌表先渲染回落地址再换直连导致下载两次、`wx:if` 与 `wx:for` 写在同一元素上作用域有歧义、整数组 `setData` 重挂载让 `lazy-load` 观察器全部失效、`alternate` + `ease-in-out` 在端点速度为零而应用恰好从端点开始。**没有一个是「加个 loading 态」能盖住的。所以验收标准不是「看起来好点了」，是「能说清之前为什么是错的」。**
- **真机读数压过工具里的观感。** 「真机上并没有动起来」「上线了，按键并不会跳转」「图片加载怎么越改越慢了」——每一次都是真机观察推翻了开发者工具里的判断，且每一次真机都是对的。凡涉及动效速度、网络耗时、跳转成功率，工具里的表现不作数（这也是「本地验证」末尾那张人工核对表存在的原因）。
- **拿不到可靠观测的问题，超过三轮就砍功能。** MTGso 外跳改了四版（跳转白名单、path、样式、让失败不再静默）仍无法在真机确认失败原因，远程调试拿不到有效日志。继续试错的次数没有上限，而这个入口本身是锦上添花，于是整个删除。**能观测才值得 debug；观测不到的锦上添花功能，删掉是最省的解。**
- **面向 cEDH 玩家说话，不面向工程说话。** 目标读者认得牌，所以组合技提示直接写卡名（`Hullbreaker Horror ＋ 低费法术力神器`）、结果直接写效果（`可以达成无限释放与无限漂浮法术力`），不写「有机会滚出风暴或法术力循环」这种既不具体、也不像玩家说话的措辞；同理外链入口不解释「MTGso 是什么」。这条已固化成门禁：`bracket.suite.js` 要求每个组合技框架的标题必须含 `required` 里的每一张牌——按这条重写标题时顺手抓出了两处标错的卡（Lumra → Lotus Cobra、Tayam → Devoted Druid）。
- **专有词查官方简中印刷文本，黑话查社区实际用语，两个来源各管一段。** 凭语感判哪个词「像编的」会系统性跑偏：这一轮先入为主认定该改的五个词——主将、导师、互动、韧性、梯度表——取证后**全部推翻**，它们都是贴吧／旅法师营地／B 站 cEDH 专栏里的真实用语（WotC 官方中文公告自己也写「少量导师牌」）。**看着像直译，不等于是编的。** 规则名词、关键词与规则动词以 Scryfall `lang:zhs` 的印刷文本为准（`指挥信标` 写「将你的指挥官从**统帅区**置于你手上」，`琉晶研究` 写「**抓**一张牌」，`靡华学徒` 写「**魔艺**」，`凿灵钻` 写「**失去生命**」）；官方清单名取 WotC 中文公告（Game Changers = **主宰牌**，Mass Land Denial = **大规模炸地**）。据此换掉的才是真编的：`咏唱`（日系词，官方是「施放」）、`抽牌`（官方是「抓牌」）、`攻击力／血量`（炉石说法，万智牌是「力量／防御力」）、`法术力物`（不存在的词）、`主将区`（官方是「统帅区」）。**合作方授权收录的内容一个字不动**——cEDH 小屋自己把榜叫「梯度表」，那它就是梯度表。
- **「按你的想法来」是有前提的授权。** 这句每次都出现在取舍已经摆清楚之后，不是空白支票。反过来讲：动手前先把方案和代价说明白，才换得到后面的放手。

## 本地验证

本地检查使用 Node.js 24，与 CI 一致。前端与领域测试无需安装依赖；`cloudfunctions/community` 单独依赖 `wx-server-sdk`，通过微信云端安装，不打入小程序包。

```bash
node scripts/build-meta-tier.js     # 更新环境梯度快照后重新生成 config/meta-tier.js
node scripts/build-commander-art.js # 改过 config/commanders.js 后重新烤主将卡图直链（会联网并自检）
node scripts/refresh-commander-stats.js --verify-games --write # 同步统计并逐记录复算胜率，保存无个人信息的审查凭据
node scripts/build-spellbook-combos.js # 同步 Commander Spellbook 的两卡组合技快照（会联网并自检）
node scripts/build-planechase.js    # 重新烤竞逐时空的 50 张简中时空／异象（会联网并自检）
node scripts/build-ban-card-index.js # 更新禁牌卡图索引（单批查询，校验真实印刷 ID）
node scripts/build-hand-card-index.js # 换了开手题后更新起手卡图索引（单批查询，校验真实印刷 ID）
node scripts/build-home-voronoi.js  # 重算首页整页背景线场（打印线段统计与可见区 ASCII 预览）
npm run check                       # 语法门禁 + 全部测试 + 覆盖率/视觉复杂度诊断
npm test                            # 仅运行全部测试
npm run syntax                      # 仅检查全部 JavaScript 语法
npm run diagnose                    # 严格推荐覆盖率与视觉复杂度诊断
```

当前基线：134 个 JavaScript 文件通过语法门禁，393 项测试全绿；推荐诊断覆盖 100/100 位主将，`deadCount = 0`（基准覆盖集 397,232 个画像）。微信最终编译包体及分包限制需用官方上传工具实测。

随机工具接受安全整数上下限及跨度，小范围从 32 位整数块抽取，大范围分两次组合 21 + 32 位；每个结果分配相同大小的整数桶，舍弃不足一个桶的尾部，避免大范围浮点乘法取整及额外候选数造成的偏差。等机会依赖随机源整数块均匀、独立的假设；运行时仍使用 `Math.random`，其标准只要求近似均匀，未承诺密码学随机。停滞的注入随机源重试 128 次后报错。计算反例与来源见 [事实审查](docs/fact-audit.md)。

诊断默认使用确定性的基准覆盖集：基线/单项变化、按主将标签构造的目标画像、与近邻构筑区分的目标画像、固定种子的组合画像，以及颜色/资源引擎组合。排序复用生产逻辑中的中间舍入、拍档惩罚和低使用率多样性尾位，避免诊断模型与实际推荐分叉。有限覆盖集未命中不等于任何回答下都不可达；覆盖成功也不证明推荐的实战竞争力。需要离线穷举全部单选组合时使用 `node scripts/diagnose-coverage.js --mode=full`；该模式组合量很大，不用于日常 CI。

**不变量测试**：`tests/invariants.suite.js` 生成确定性的操作序列，检查试玩的牌数和身份守恒、估档输出边界、生命记录可存储性，以及坏存储后端的结构化错误。覆盖的是已生成输入，不是任意操作的形式化证明；抽签频数检查也不证明随机源本身均匀。试玩在持久区中移除已离场衍生物，省略其在下次状态动作前的短暂区域状态。扩大种子数量可增加采样覆盖，耗时须按机器实测。

**基线数字由测试守着**：README 里「当前基线」那几个可算的数（测试条数、语法门禁文件数、指挥官库人数、页面数）都由 `shared.suite.js` 与真值对账，改了代码忘了同步会直接红。散文里的数字没有主人——不会有人回头重算它，于是它慢慢变成一句假话，而下一个人拿它当事实用。同一条门禁还禁止任何 suite 去 `require` 另一个 suite：`npm test` 是 `node --test tests/*.js`，每个 suite 都会被直接拾取，再 require 一遍只会让它们跑两遍、把条数报虚（曾有 `tests/core.test.js` 这么干，把 262 条报成 349 条）。

发布前应确认：`npm run check` 全绿（语法门禁 + 测试 + `deadCount` 为 0）、Scryfall request + downloadFile 域名与隐私保护指引已配置、AppID 为正式主体。

`radial-gradient` 与「异步 wx API 不得无参调用」两项已由 `shared.suite.js` 的门禁自动校验，不再需要人工逐页检查——**能自动化的检查项就不要留在检查单上让人肉眼过**，人工那一栏只保留 Node 测不到的东西（见下）。

### 改动交付与 GitHub 同步
