# 赛事月报

`pages/meta/meta` 默认展示赛事月报，原有署名梯度保留在小屋编辑榜。云函数 `metaMonthly` 在现有环境和 `community` 集合内使用 `meta_monthly_` 命名空间；客户端仍不能直接读写集合。月报不参与 Bracket 规则判定。

## 数据与计算

数据来自 [TopDeck V2 API](https://topdeck.gg/docs/tournaments-v2)，主将以 Scryfall Oracle ID 归一化，拍档顺序不影响合并。公开数据免费展示，API key 仅在服务端使用。开发者条款 §6.1 要求在用户看到数据的地方署名并给链接，所以首屏、详情和页脚都有“数据来自 TopDeck.gg”，点击复制链接；小程序个人主体不能打开外部网页。条款 §7 禁止授权 API 数据，仓库里的快照在 [NOTICE](../NOTICE.md) 中排除于 MIT 之外。

主将显示名的优先顺序是编辑榜写法、[官方简中印刷名](../cloudfunctions/metaMonthly/commander-names.json)、英文。威世智 2024 年起基本停了简中，这份名表由 `scripts/build-commander-names.js` 从 Scryfall 生成后入库；2026-10 的 386 位主将有 245 位显示中文，排名区还显示英文的 7 位确实没有官方简中。

月报以 UTC 月末为截止，取开赛日期落在此前 90 天且实际完赛早于截止的赛事。要求 EDH、至少 50 名实际参赛者、至少四轮瑞士轮、主将覆盖率和四人桌比例均不低于 80%。排除团体、联赛和名称明确标记的预组、贫民、Bracket 1 到 4、特殊规则赛事及主办方的测试赛（Bracket 5 就是 cEDH，保留）。名称过滤不能辨识所有自定义赛事，排除原因与覆盖率随快照保留。

赛事以欧美为主：2026-10 约 75% 的参赛在美国，中文地区 0 场，Beijing Spotlight 因主办方没有录入主将被排除。页面副标题和统计口径都写明这一点，读者不应把它当成国内环境。

瑞士轮只统计四人已完成牌桌。平局使用 API 明确的 Draw 标记；Unknown 不当成平局。轮空与淘汰轮不进入胜率。晋级名单必须由全部淘汰轮实际参赛者并集验证，不能直接把最终名次前 N 名当成晋级者。

模型 `relative-performance-v1`，基准分为 50。令全样本胜率为 μ、晋级率为 q，某组合的瑞士轮胜场 W、对局 G、晋级 K、按各赛事名额比例累计的预期晋级数 E：

```
p = (W + 80μ) / (G + 80)
c = (K + 40q) / (E + 40q)
score = 25 × (p/μ + c)
```

胜率与晋级表现等权，出场占比单独展示。80 对局、40 次参赛是本版本固定的收缩参数，未宣称是经优化的最优参数。按赛事聚类重采样 4000 次，使用固定全样本基准，取 95% 分位区间。最初用 240 次，同一份数据换随机种子就有 7% 的排名行换档，4000 次降到 2% 以下，本机构建一期只多约 0.5 秒。它衡量已观测样本的不确定性，不是未来胜率预测。

分档要求至少 20 次参赛、5 位独立牌手、3 场赛事和 20 次可验证晋级机会。区间完全高于 50 为领先，跨 50 为竞争，完全低于 50 为承压；其余进入观察中。跨期变化只在模型版本相同时计算。

分档要这样读：把主将标签在每场赛事内随机打乱后，仍有约 7% 的行被标领先或承压，名义值是 5%。2026-10 真实标出 14 行，其中约 4 行纯靠偶然也会出现。2026-07 与 2026-10 两个不重叠窗口的表现分等级相关约 0.60，说明有真实信号，但领先档逐月只留下不到六成。页面因此写明单月升降不等于强弱变化。

## 自动运行与恢复

`config.json` 的 timer 为 `0 17 * * * * *`，北京时间每小时第 17 分钟执行。UTC 每月 1、2 日宽限，3 日起采集上一月，完成后当月后续触发仅检查状态。任务卡住时不会有人收到通知，所以到 6 日还没有上一个月的月报，页面会提示新一期还没生成；原因用维护端 `status` 查。每次最多验证四场赛事，遇到限流/网络失败保留旧月报并从游标重试。事务租约防重入；每场赛事完成即落检查点。

发布顺序是写不可变快照、读回校验、事务切换月份索引。失败不会替换已发布数据；历史回填不会把最新月份倒退。前端校验结构、缓存六小时，断网显示已保存月报与重试状态。公开快照不含牌手 ID；私有检查点只保留散列标识，不采集姓名或联系方式。检查点只为当期计算存在（开发者条款 §8.2），发布成功后删除，删除失败下一轮重试且不影响已发布月报；上个月卡住没跑完的任务，下个月开始时一并清掉。

## 首页更新日期

首页“环境梯度”后面显示电光蓝的“X月X日更新”，取自月份索引里的发布时间，按北京时间显示。首页不拉五百多 KB 的整份月报，只调用公开的 `latest`，返回最新一期和发布时间；结果记在本机 `metaMonthlyLatest`，六小时内不再问。赛事月报页拉到最新一期时也会顺手记下，`get` 因此也带上发布时间。读不到或云函数还是旧版时，日期不显示，首页不弹提示。

同一份内容重新发布（比如重跑 `seed`）不算更新，发布时间沿用原来的；补发旧月份不改最新一期的日期。首页点阵字体子集为此补了“月日更新”四个字，取自同版本完整字体，原有字形逐字节不变。

## 部署

`scripts/deploy-monthly-meta.ps1` 一步完成下面第 2、3 步的代码上传和暂存清理，Windows PowerShell 5.1 就能运行。运行时别关窗口：窗口被关时收尾不会执行，密钥副本会留到下次运行才被清掉。代码更新后还要调用一次 `seed`，随函数携带的快照才会发布。

2026-11-06 第一次用真实 CLI 跑这个脚本：部署成功了，脚本却报 `DEPLOY_FAILED`，暂存目录连同密钥副本也没删掉。CLI 的结果表是 UTF-8，PowerShell 5.1 按本机的 gb2312 读，表格竖线变成汉字，成功判断就匹配不上；收尾删目录时 CLI 留下的子进程还占着日志，删除第一下就失败。副本留了约两分钟，发现后覆盖明文、移到回收站。它只在本机同一账户的临时目录里，同样的值本来就在这个账户的环境变量中，所以没有更换 key。

现在日志按 UTF-8 读，成功判断不依赖分隔符；收尾先抹掉密钥副本，再重试删目录，删不掉时只剩日志和公开代码；上次留下的目录被锁着时，也不再挡住下一次部署。用模拟真实输出的假 CLI 对照过：旧脚本在 UTF-8 表格、子进程占着日志、成功后卡住三种情况下失败，新脚本六种情况全部通过。

要彻底不在本机生成密钥副本，可以在云开发控制台给 `metaMonthly` 配置环境变量 `TOPDECK_API_KEY` 和 `META_ADMIN_TOKEN`（函数优先读环境变量），之后部署就用不着 `runtime-secrets.json`。脚本目前还没有跳过这个文件的开关。

1. 本机用户级 `TOPDECK_API_KEY` 已配置。另创建至少 32 字符的随机 `META_ADMIN_TOKEN` 用于维护操作。两者均不进入 Git、聊天或前端。
2. 将 `cloudfunctions/metaMonthly` 复制到私有临时目录，并仅在该目录生成忽略文件 `runtime-secrets.json`，字段 `topdeckKey`、`adminToken`。支持用服务端环境变量替代该文件。
3. 使用官方 DevTools CLI `cloud functions deploy --env cloudbase-d6gvqujh4d0efe37f --paths <临时目录>/metaMonthly --project <实际开发工程> --remote-npm-install`。在原生云开发控制台将超时设为 60 秒、内存保留 256 MB。CLI 代码上传不会创建触发器，需在实际工程中右键本函数的 `config.json`，选择「上传触发器」，再到云函数详情刷新确认线上规则。
4. 维护端可调用 `status` 查看进度、失败次数、检查点是否已清理与最近定时触发时间。维护端调用 `seed` 发布随函数携带的历史回填，再调用 `tick` 实测检查点。普通调用只允许 `get`；伪造 event.Type 或 action 不产生维护权限，定时任务通过服务端 SOURCE 判断。
5. 删除本次私有部署暂存。用公开 `get` 验证月份、哈希、覆盖率和列表，再验证小程序的搜索、筛选、详情、缓存和离线状态。

本地回填命令需显式指定私有缓存位置，缓存保存赛事原始 API 数据，不进入仓库：

```
node scripts/build-monthly-meta.js --period 2026-10 --cache <私有目录> --previous <上月快照.json> --output <聚合快照.json>
```

当前复用现有 CloudBase 环境，无新增订阅或付费 API。调用量、计算量记入原套餐；没有设置自动购买或升级套餐。套餐与余量还没有核实，要看后台。
