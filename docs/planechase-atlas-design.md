# Planechase：界面一致性与结算交互

日期：2026-09-05。本轮根据用户的一致性反馈修订 `e4613ed` 的视觉方案。文件名保留，便于已有评审链接继续访问；当前实现以混沌工具及相邻功能页为参考。

## 当前设计决定

竞逐时空是对局中的功能页，背景、面板和按钮应遵循功能页的共享样式。移除独立图鉴色板、纸白规则页、直角按钮、巨型页眉和封面入口。

| 环节 | 当前实现 | 共享来源 |
| --- | --- | --- |
| 背景 | 黑色渐变、混沌工具紫粉强调色、相同粒子组件 | `dark-table.wxss`、`particle-background palette="random"` |
| 页面布局 | 全局页边距与间距；常规页标题、统计面板、圆角视图切换、卡牌面板 | `app.wxss`、`tokens.wxss` |
| 阅读区 | 暗色半透明面板、白色正文、柔和混沌强调区，保留完整规则 | `.surface`、共享 surface/accent token |
| 按钮 | 主操作直接继承 `.primary-button` 的背景、描边、圆角与内高光；其他控件使用共享输入底色和圆角 | 全局按钮与主题 token |
| 工具入口 | 与卷心菜、伊捷风暴并列的普通入口卡，相同内边距、标题字号、圆角和投影 | `.random-panel.surface.tool-entry` |
| 固定操作与弹层 | 仍使用不透字的深色底，卡面关闭、重试及完整文字可用 | 共享深色语义变量 |

标题采用现有衬线字体，正文沿用全局中文阅读字体；没有添加字体文件或新依赖。按钮最小热区仍为 44×44 CSS px，规则正文为 14px。粒子只是背景表现，牌局提交不等待动画。

## 保留的交互约束

- 当前时空与结算台可切换；步骤改变后展示当前任务。多张时空均可读，多来源能力由玩家指定。
- 浏览卡文、展开复制/反击选项不改牌库、不写存档、不消耗撤销。
- 从卡文页进入待处理步骤时，第一次点击只展示结算内容。
- 单一来源可从底栏结算；多个来源不按显示顺序自动选取。
- 保存失败停留在已提交状态，重试同一候选；旧按钮连点不能执行新步骤。
- 卡图失败仍有占位和完整卡文。弹层打开与页面卸载后，背景操作及迟到的滚动回调受保护。

牌局 reducer、牌张快照及 schema 2 存档格式不变。完整 MTG 堆叠、实体牌状态和费用支付继续由牌桌裁定。

## 验证

- 104 个 JavaScript 文件语法检查，320 项现有测试回归；无新增仅镜像 CSS 的测试。
- 15 个 WXML、20 个 WXSS 文件通过本机微信工具附带的原生编译器。
- 320px 与 430px 各检查普通状态、待结算、展示排序、多来源、多时空、长卡文、卡图失败、保存失败、失败卡面弹层与工具入口，共 20 组；未发现横向溢出或小于 44px 的按钮热区。375px 检查读牌与单来源结算版式。
- 浏览器计算样式比较：竞逐时空与混沌工具的页面渐变、主按钮背景、圆角和投影完全相同。同组三个工具入口的内边距、标题字号、圆角和投影相同。
- 预览使用实际页面控制器和原生 WXML 编译产物，微信存储与导航为隔离适配。浏览器预览不渲染原生粒子 Canvas；共享组件已接回小程序，实际动态表现仍需微信真机检查。
