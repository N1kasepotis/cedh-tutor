# Planechase：图鉴与结算台

日期：2026-09-05。改动基于规则加固提交 `58552b2`，面向原生微信小程序的手机牌桌场景。本轮完成可交互的视觉与布局实现；商业发布条件仍以 [预商业化审查](precommercial-review.md) 为准。

## 设计决定

核心任务分为读懂当前时空、处理待结算能力、执行下一次操作。原来的长页面把设置、提示和所有能力堆在卡文前面，主视觉和实际操作都会被挤出首屏。

选定「时空图鉴 × 牌桌仪表」：横幅原画、宋体大标题、纸白规则区、黑色台面及首页的信号黄。混沌效应使用独立的粉色区域与明确标题。相比全屏沉浸式原画，这一方向可以稳定容纳长卡文；相比纯表格式控制台，它能保留万智牌的画作与世界感。

- 当前时空：卡图、牌名、类型、完整规则和混沌规则保持清晰的阅读顺序。多个时空分别展示，不能折叠成只显示一张。
- 结算台：步骤变化后自动展示当前任务。保留当前所有牌名的卡面入口；复制与反击收在有名称的展开按钮内。
- 底部操作栏：普通骰显示费用；单一能力直接提供对应结算动作；多个来源要求玩家选择。浏览卡文时，底部按钮先进入结算台，不会直接确认展示顺序或牌桌事项。
- 入口：混沌工具顶部使用同色板的图鉴封面，名称、用途和进入动作明确。首页仍保持八个入口。
- 视觉变量集中在 `styles/themes/dark-table.wxss`，图鉴展示字体集中声明，正文沿用本机中文阅读字体。没有新增字体下载、依赖或运行时动画计时器。

## 交互不变量

| 操作 | 必须成立的条件 |
| --- | --- |
| 切换视图、展开选项、查看卡面 | 不改牌库、不写存档、不消耗撤销、不产生随机结果 |
| 存储失败 | 仍停留在已提交的牌局与阶段；重试保存同一候选 |
| 从读牌返回待处理步骤 | 第一次点击只展示结算内容 |
| 多个能力来源 | 不根据显示顺序自动选择来源 |
| 连续点击底部按钮 | 旧画面的按钮版本不得提交新画面的动作；保护不依赖延迟计时器 |
| 卡图失败 | 本地图鉴占位、完整卡文、结算操作仍可用 |
| 页面卸载或卡面打开 | 延迟的滚动回调不得移动其他页面或背景内容 |

牌局 reducer、50 张牌的快照及 schema 2 存档格式均沿用已加固版本。

## 已执行验证

- JavaScript 语法：104 个文件；全仓测试：320 项。新增 5 项真实控制器测试，涵盖视图无副作用、先展示再确认、多来源、保存失败和旧按钮连续点击。
- 原生模板编译：15 个 WXML、20 个 WXSS 文件通过本机微信开发者工具附带编译器。编译通过不等于微信运行时验收通过。
- 浏览器预览由实际页面控制器和原生 WXML 编译结果生成。320px 与 430px 各检查普通状态、待结算、展示排序、多时空、最长普通卡文、卡图失败、保存失败、失败卡面弹层、混沌工具入口，共 18 组。所查页面无横向溢出，按钮热区不小于 44×44 CSS px；另在 375px 检查主视觉和单来源结算。
- 实际点击检查：展示牌置底排序后确认换入两张时空；入口调用导航进入 Planechase。微信 API 使用隔离的预览适配，未读取或写入用户真实对局。
- 配色计算：规则正文 14.71:1、纸面辅助文字 6.30:1、混沌标题 6.99:1、主按钮 13.66:1、暗色辅助文字 9.70:1。这是指定实色组合的计算结果，不代表整页已通过无障碍认证。
- 规则可达性严格诊断仍为 100/100、deadCount 0；该指标衡量主将推荐覆盖，不证明推荐准确率或视觉质量。

本地预览不覆盖微信字体放大、读屏焦点、基础库差异、真实缓存和网络调度。素材来自既有 Scryfall 地址，失败时呈现离线内容；没有通过下载替代图片展示限制。
