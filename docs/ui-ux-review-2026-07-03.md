## A · 行为与可靠性（建议优先处理）

**A1. 删除牌组没有确认弹窗** `pages/tracker/tracker.js:169`
现状：点一下卡片右上角的小字「删除」，整套牌组连同全部对局历史立即消失，不可恢复。对比：清空数据、长按删对局都有确认。
建议：加 `wx.showModal`（标题「删除牌组」，正文「会删除该主将的全部对局记录。」），风格对齐现有「清空战绩」弹窗。
成本：小。

**A2. 删除单条对局的保护是反的** `tracker.js:237`
现状：每行可见的「删除」按钮直接删（无确认）；隐藏的长按手势反而弹确认。误触率最高的路径没有保护。
建议：可见按钮改走现有 `confirmDeleteMatch` 确认流程；长按保留。
成本：小（一行改动）。

**A3. quiz ↔ result 循环 navigateTo 会撑爆页面栈** `quiz.js:104`、`result.js` restart
现状：完成问卷 `navigateTo` result，「重新匹配」又 `navigateTo` quiz……小程序页面栈上限 10 层，反复重测会到达上限后跳转静默失败。
建议：这两处互跳改 `wx.redirectTo`（替换当前页，不叠栈）。
成本：小。

**A4. EDHTI 导出画布在高分屏真机可能导出失败** `edhti.js` drawEdhtiPoster
现状：edhti 画布尺寸乘了 DPR（750×1624×3 ≈ 2250×4872）；result 页早已发现「过大画布导致 canvasToTempFilePath 失败」并改为固定像素（其注释仍在），edhti 没跟进，画布反而比 result 更大。
建议：与 result 统一为固定像素策略（如 1080×2340 不乘 DPR），导出清晰度也随之统一。
成本：中（需真机回归导出效果）。

## B · UX 补齐

**B1. 多选题没有任何「可多选」提示** `quiz.wxml`
现状：问卷里 `type: 'multiple'` 的题和单选题外观完全一样，用户不知道能多选（点第二个选项时可能以为是换选）。
建议：多选题在题面板加小标签「可多选」（复用 `.question-bucket` 风格），选项选中数 ≥1 时按钮文案不变。
成本：小。

**B2. tracker 无牌组时是一个空页面 + 孤零零的「+」** `tracker.wxml`
现状：新用户进入只看到一个巨大的「+」按钮，无引导。
建议：加空状态（复用 result 页 `.empty` 样式）：「还没有主将战绩 —— 点击 + 记录你的第一套牌组」。
成本：小。

**B3. 卡图加载中/失败无占位** `result.wxml`、`edhti.wxml`
现状：Scryfall 请求返回前，推荐卡片的图片区域是空白；请求失败则永远空白（数据里有 `loading` 字段但 UI 未用）。
建议：加载中显示主题色底纹占位；失败保持底纹并保留文字排版（文字本就在图上层，不破版）。
成本：中。

**B4. random 页前两个面板没有标题** `random.wxml`
现状：只有第三个面板有标题「_____ Goblin 开局贴纸」，前两个面板（随机数、先手判定）功能靠猜。
建议：补 `panel-title`：「随机数」「先手判定」。
成本：极小。

**B5. 「再测一次」直接丢弃 20 题答案** `edhti.js` restart
现状：结算页误触「再测一次」，20 题白答，无确认。
建议：加确认弹窗（「重新开始测试？当前结果将被清除。」）——或先做 A 组，此项你若觉得打断感更差可以拒。
成本：小。

**B6. 无障碍基线** 全站
现状：全站仅 2 个 aria-label；交互控件几乎全是 `<view bindtap>`（读屏不识别为按钮）；「+」按钮无名称；主页按钮英文装饰字 16rpx（约 8px）会被读屏朗读。
建议：交互 view 补 `aria-role="button"` + `aria-label`；「+」加「添加牌组」；装饰性英文加 `aria-hidden="true"`。
成本：中（机械性，约 20 处）。

## C · 文案与命名

**C1. 同一功能三套名字** 入口 / 导航栏 / 页内
现状：人格测试↔EDHTI；火花觉醒↔指挥官问卷；我的主将↔指挥官战情室；混沌工具↔小工具。用户从入口进去后导航栏换了个名字，认知断裂。
建议：定一张命名表，入口与导航栏一致（页内可用风味副标题保留个性）。需要你拍板每个功能的正式名。
成本：小（决策为主）。

**C2. 「火花觉醒 / SPARK ZONE」不达意** `index.wxml:46`
现状：四个入口里唯一猜不出功能的（其实是主将推荐问卷）。specific beats clever。
建议：改为「主将匹配 / MATCHMAKER」或「本命主将 / SOULMATE」等直白名（与 C1 一起定）。
成本：极小（涉及测试断言同步）。

**C3. 「导出数据」实际是复制到剪贴板** `tracker.wxml:121`
建议：改「复制战绩文本」，动作与结果一致（toast 已是「已复制」类文案）。
成本：极小。

**C4. 「导出失败」toast 无下一步** `canvas-kit.js`
建议：改「导出失败，请重试」；权限拒绝场景已有去设置弹窗，无需动。
成本：极小。

**C5. 指挥官输入框 placeholder 缺示例** `tracker.wxml:18`
建议：「输入指挥官名称，如 Kinnan」。
成本：极小。

**C6. feedback 页没有中文标题** `feedback.wxml`
现状：只有英文 eyebrow「FEEDBACK」，正文直接开始。
建议：加中文标题「反馈建议」（与主页印章、导航栏「建议通道」统一命名，见 C1）。
成本：极小。

## D · 排版（中英混排与标点）

**D1. 中英文之间缺空格（盘古之白）** 多处
现状：「竞技EDH导师」「掷 4 个D20 骰子」等；两张导出图 footer 都有。
建议：统一「竞技 EDH 导师」「掷 4 个 D20」。注意：`tests/ui.suite.js`、`edhti.suite.js` 有对旧字样的断言，需同步更新。
成本：小。

**D2. 联名符号「X」应为「×」** `edhti.js` drawEdhtiFooter
现状：导出图 footer「竞技EDH导师 X cedh小屋」。
建议：「竞技 EDH 导师 × cedh 小屋」（与 D1 一起改）。
成本：极小。

**D3. 贴纸免责声明 14rpx 过小** `random.wxss`
现状：比全站最小字号 token（20rpx）还小 30%，基本不可读；规则性说明应可读。
建议：提到 `var(--cedh-text-10)`（20rpx）。
成本：极小。

## E · 导出海报

**E1. result 导出图含卡图但无版权署名** `result.js` drawHeritageExportPoster
现状：页面内有「图像来自 Scryfall，美术版权归 Wizards of the Coast 及画师」，但会被分享出去的海报上没有。合规风险最高的恰恰是传播面最大的物料。
建议：海报 footer 上方加一行小字署名（英文一行即可：Art via Scryfall · © Wizards of the Coast）。
成本：小。

**E2. 两张海报的 footer 规格不一致**
现状：edhti 海报 footer 是「双码 + 两行文案」左对齐，result 海报是「单码 + 一行标题」居中；同一产品的两张分享物料，品牌收尾不一致。
建议：统一 footer 版式（建议以 edhti 版为基准，result 补 cedh 小屋码与引导文案），并与 D1/D2 文案修正同步。
成本：中。

## F · 视觉打磨（可选）

**F1. 进度条 2rpx 太弱** `quiz.wxss` / `edhti.wxss`
黑底上 0.16 透明度的 2rpx 线几乎不可见。建议 6rpx + 保持现有渐变。

**F2. result 卡片文字叠图对比度** `result.wxss`
长英文卡名叠在明亮卡图上时 text-shadow 不够。建议卡图上加一层 40% 高度的底部 scrim 渐变。

**F3. 小屏适配** 全站
全站只有 result 有一条 media query；index 标题 108rpx + 固定宽按钮在 320px 级设备可能溢出。建议给 index/tracker 补 360px 断点。

## G · 结构延伸（重构第三阶段的遗留决策）

**G1. option-list 组件化** `edhti.wxml` + `quiz.wxml`
两页选项列表 markup 相同但选中态视觉不同（霓虹粉蓝渐变 vs 黑金）。组件化前需决定：保留两套主题选中态（组件消费主题变量，推荐）还是统一视觉。批准后我会做成消费 `--cedh-*` 变量的自定义组件，两页像素不变。
成本：中。

**G2. 空态样式全局化**
result 的 `.empty` 系列样式移入 app.wxss 作为共享 class，供 B2 及未来页面复用（若 B2 批准则顺带做）。
成本：极小。
