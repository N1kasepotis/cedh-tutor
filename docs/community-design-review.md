# EDH hub 设计审查

本轮按用户要求先评分，再逐页重构。设计判据来自 bencium-controlled-ux-designer、README「视觉规则」「改动口径」及 docs/ux-goals.md；文案按 stop-slop 检查。下表是对照同一标准的设计自评，不代表外部团队或真机用户评分。

## 对局约定加预览牌与鸡飞牌（2026-09-18）

用户在手机上看了对局约定后，要求加“是否使用未来的官方预览牌”和“是否允许有趣但是不会过于强力的鸡飞”。“鸡飞”是国内玩家对 Un 系列搞笑扩充的叫法（Unfinity 叫“鸡飞4”，Unsanctioned 叫“鸡飞预组”），界面沿用玩家叫法写作“鸡飞牌”。

- 标签：“新系列预览牌”“鸡飞牌”，放在“代牌”后面，三项说的都是能用哪些牌
- 选项：预览牌是“可以用 / 聊完再定 / 不用”，与代牌一致；鸡飞牌是“不太强的可以 / 聊完再定 / 不用”，把“有趣但不过于强力”写进选项
- 默认：新桌两项都是“聊完再定”。旧约定、旧链接和旧版小程序发来的约定没有这两项，也记作“聊完再定”，不替玩家做决定；原有五项仍然必填
- 选项与默认值的提问用户没有作答，直接要求改完测试后部署，以上按推荐做法落地，可以再调

## 撤回后再分享换新链接（2026-09-15）

分享链接的地址由作者和草稿身份算出。原来撤回后再点“生成分享”会用回同一个地址，牌友手里的旧链接又能打开，和撤回提示“之前收到的链接会看不到”不一致。用户选择再分享时换新链接：名片页和对局约定分享一份已撤回的内容时，先换一个草稿身份再发布，旧链接一直打不开；对局约定的本机记录替换掉旧的那条，不留重复。只改小程序，云函数不用重新部署。

## 少用功能挪到最下方（2026-09-15）

用户要求把少用的功能挪到最下方，撤回分享链接居中放在页面最下面；其余几处由用户逐项勾选。统一做法：放进 `quiet-footer` 居中，13px 常规字重、次要文字色的文字链接，按钮只占文字宽度，热区仍不小于 44px。

- 三张牌认识你、对局约定：“撤回分享链接”放到整页最下面，名片页在版权说明之后，约定页在已存约定之后
- 禁牌投票：“撤票”从选项正下方挪到票数统计之后
- 禁牌表：“复制公告链接”从卡牌信息与投票之间挪到详情页最下面；“复制官方禁牌表链接”挪到列表页版权说明之后
- 调牌记录：每条记录里与“复盘”并排的“删除”改成这条记录底部居中的文字链接，仍先弹窗确认
- 这手留不留：“复制来源链接”从来源判断面板挪到页面最下面，看过来源判断才出现
- 取舍：这些操作离对应内容远了一点（撤票不再紧挨选项，复制来源链接不再紧挨来源名称），换来主流程里只剩主操作

## 首页入口整行点阵字（2026-09-15）

用户要求首页入口“名片 / 禁牌 / 条约 / 练习 →”整行都显示成点阵字。

- 字形来源：本机 FOF 项目里的 `fusion-pixel-10px-zh-hans.woff2` 解开后是完整的 Fusion Pixel 10px Mono zh_hans 2026.07.01（CFF 轮廓，24526 个字形），与首页子集同一版本、同一变体，所以没有另外下载
- 核对：子集原有 137 个码位的字形，从这份字体转成 TrueType 轮廓后逐点一致（起点和点序都相同），字宽和竖排度量也一致，补进来的字因此与官方 TTF 相同
- 做法：用 fontTools 只往原子集追加“名、片、禁、条、约、练、习、→”8 个字形并写进 cmap；原有字形编码后逐字节不变，name、OS/2、post、hhea、vhea 表不动，head 保留原来的字体边界框。子集从 14452 字节变为 15612 字节，再跑 `node scripts/build-home-pixel-font.js` 生成内嵌 base64
- ui.suite 新增门禁：首页 WXML 的静态文字必须全部落在子集 cmap 里，入口改字没补字会直接变红
- 以后补字：拿同一版本的 Fusion Pixel 10px Mono zh_hans（官方 release 的 TTF 或 OTF 都行），照上面只追加缺的字形，并核对原有字形不变

## 发布前设计决定（2026-09-15）

扫查后用户逐项拍板：

- 入口页去掉“EDH / COMMANDER”小字，只留大标题 EDH hub
- 入口卡片和禁牌列表的箭头统一成 ›，与随机工具页的入口一致
- 首页入口副标题从“选牌 / 开局 / 复盘 →”改为“名片 / 禁牌 / 条约 / 练习 →”，与入口页现有功能对应。首页点阵字体子集没收全入口这一行的字：旧副标题的“选、局、复、盘”和箭头一直由备用字体显示，新副标题除“牌”以外同样走备用字体。用户随后要求整行显示成点阵字，已补齐，见上一节
- 禁牌表投票改为点选项即投票，去掉“投票 / 改票”和“刷新票数”；撤票改成次要文字链接，投过票才出现
- 对局约定改选项就自动存本机，去掉“保存本桌”；“生成分享 / 更新分享”与“发给牌友”共用一个位置；回到页面时静默刷新确认人数，去掉“刷新确认状态”；朋友打开时“没问题”是主按钮
- 分享按钮统一叫“发给牌友”，与微信“发送给朋友”的叫法一致

## 发布前设计扫查（2026-09-15）

按 bencium-controlled-ux-designer 与 Web Interface Guidelines 把 EDH hub 六页、投票与选牌组件、共用样式扫了一遍。按技能要求，颜色、字号、布局这类设计取舍先问用户，这次只改用户点名的一处和不改变视觉方向的问题：

- 入口页“我的三张牌”卡片去掉“三张牌认识你”这行字（用户要求），卡片下沿空白随之收紧，按钮补读屏名称“我的三张牌”
- 六页的 `backgroundColor` 补成与导航栏相同的 `#070707`：原来继承全局白底，iOS 上下拉过头会露出白色
- 装饰箭头（入口页的 ↗、禁牌列表的 →）不念给读屏；名片短评、禁牌搜索、选牌搜索、调牌复盘四个只有占位字的输入框补读屏名称
- 名片图片的“完整卡牌”“只看卡画”由 `text` 改成带按压反馈的 `view`，读屏名称带上是否已选；起手卡图瓦片补按压反馈
- 起手瓦片缺图时退回的牌名从 15rpx（约 7.5px）提到 10px，满足 docs/ux-goals.md 功能文本不小于 10px 的下限

留给用户决定的：入口页小字“EDH / COMMANDER”与标题重复；入口页 ↗ 箭头与站内其他页面的 →、› 不统一；首页入口副标题“选牌 / 开局 / 复盘”与现有功能对不上（改字要重新生成首页点阵字体子集）；禁牌表与对局约定的按钮是否按名片页的思路精简；“分享给牌友”和“发给牌友”两种说法。

## 撤回分享链接（2026-09-15）

用户反馈“停止分享”会让人诧异：刚分享完就看到它，像是有什么一直在进行、需要去关掉。操作本身保留，它是作者收回已公开内容的唯一途径，只改说法、位置和确认：

- 名片页与对局约定统一叫“撤回分享链接”，直接说明作用在链接上
- 名片页挪到页面最下面、图片按钮之后，不再紧挨“分享给牌友”；两页的链接颜色都降到次要文字（`quiet-link`）
- 点了先弹窗。名片写“牌友再打开之前收到的链接会看不到这张名片，本机草稿不受影响”，约定写“牌友再打开之前收到的链接会看不到这份约定，本机保存的约定不受影响”，确认按钮是“撤回”，与删除调牌记录同一种确认强度。撤回后 Toast 提示“已撤回”，之后仍可重新生成分享

## EDH hub 改名、禁牌投票与名片操作区（2026-09-15）

- 改名：分区名“EDH 牌桌”改为“EDH hub”，首页入口、入口页标题与导航栏、各功能页抬头和入口页分享标题一起换，测试扫描 miniprogram 挡住旧名
- 禁牌表投票不再区分牌手类别：去掉“补充投票信息（选填）”里的“平时玩”（不填写、休闲 EDH、cEDH、两者都玩）和票数上方的视角筛选。同一块里的“理由”也去掉，它只存进票里，没有任何页面显示。投票只交立场，票数只看全部参与者；服务端契约仍接受类别字段、缺省时记作未填写，不需要重新部署；本机旧表态里填过的类别照样能读
- 三张牌认识你底部：草稿在选牌、离开输入框和离开页面时自动存本机，去掉“保存到本机”；“生成分享名片”成功后原位换成“分享给牌友”；“生成名片图片”生成后原位换成“保存到相册”，预览图在按钮上方；“只展示卡画”开关改成标题右侧“完整卡牌”“只看卡画”两个文字选项，热区保持 44px，并与下方按钮拉开间距。成功不再写一行提示，靠按钮变化和 Toast 表达，操作区上方只留出错提示
- 分享和生成图片同时只会进行一件，按钮只让正在进行的那一个转圈

## 去掉顶部色条与英文抬头（2026-09-14）

用户认为海报标题下那截彩色短线意义不明，“cEDH Tutor / PLAYER PROFILE”抬头也不需要，要求去掉。本节优先于下文关于强调色和抬头的描述。

- 顶部直接从署名开始：署名基线从 184 上移到 140，字顶到画布上沿的留白与左右边距相当
- 标题下保留与三张牌之间同样的 1px 灰色细线作分隔，只去掉压在细线左端的彩色短线
- 强调色只剩这一处用途，去掉后从第一张卡画取主色的逻辑（`accentFrom`）和对应测试一并删除，海报不再读取卡图像素
- 测试改为锁住：署名上方没有任何文字，画面里没有抬头；色块只剩整幅底色与暗角、整宽灰线和颗粒，填充只剩卡牌投影底板和小程序码白底

## 去掉标签与点号（2026-09-14）

用户要求去掉名片标签，并全局去掉点号。本节优先于下文“暗色收藏档案 × 玩家批注”里关于标签、类别记号和部署的描述。

- 标签整体撤回：契约恢复到加标签之前的名片字段（署名、套牌名、三张牌），云函数副本同步恢复，与线上 `5410fdd` 的服务端校验一致，不再需要为标签重新部署。编辑页的三行选择器、牌友分享页的标签和海报署名下的标签框都去掉，测试挡住标签被加回
- 点号指 `·` 这类中点，用户此前说“赛后一分钟（点号）选填”时指的就是界面上的“赛后一分钟 · 选填”。全站产品文案里剩下的四处换掉：海报收藏注释改成“MSC #143 / EN”；试玩页区面板的标题与张数之间、“加载更多”与计数之间改用全角空格；随机工具里竞逐时空的副标题改成“共享时空套牌与时空骰”，与读屏标签一致
- 海报三类选牌前的圆点也是点。圆点、菱形、四角星三个小记号一起去掉，只留文字标签，强调色只剩标题下的一截短线
- 官方中文牌名里的间隔号（诺曼·奥斯本、比比·奥尼提尔）是牌名原文，保留。竞逐时空旧存档里的“ · ”分隔在显示时换成逗号，这段兼容代码改用转义写法，源码里不再出现点号
- 门禁：`shared.suite.js` 扫描 miniprogram 下全部 WXML、WXSS 与 JS，先剥掉注释，只放行前后都是汉字的间隔号

## 三张牌名片海报：暗色收藏档案 × 玩家批注（2026-09-14）

用户给出一份海报改版建议，本节取代后文“名片海报深暗极简”和“三张牌名片：小程序码、提示语与选牌”里关于海报版式的部分；选牌弹层的行为不变。

- 阅读顺序改为认识玩家 → 读三张牌 → 底部接力。署名是全图最大的字（76px 半粗），下接“三张牌认识我”，再下面是玩家自选的标签；小程序码从右上角移到底部参与区
- 标签：玩家在对局强度、套牌速度、干扰对手三项里各挑一个或不填。词汇直接取对局约定的强度分级和问卷里的速度、干扰选项（Turbo、中速、控制；Stax 锁场、适度互动、康完你的康他的、各扫门前雪），没有新造的词，测试逐项比对这两处来源。海报和牌友打开的分享名片只显示玩家选过的标签，不根据所选卡牌推断：喜欢一张牌的美术，不代表喜欢对应的打法
- 栏目含义：沿用“常用妙妙牌”（本项目和用户已在用的词），短评提示改问“它在你的牌组里妙在哪？”，让短评说清它特别在哪里；另两类分别问“原画、规则设计还是实战体验？”和“用它说说你喜欢怎么玩”
- 三张牌共用同一骨架，只换类别前的小记号：设计是圆点，打法是菱形，妙妙牌是四角星。短评 30px、颜色最亮；牌名收到英文 26px、中文 28px，中文印刷版本附小号英文原名；版本、编号和语言改用等宽小字写在卡图下方，作收藏注释
- 质感：底色从冷黑 `#050507` 换成微暖墨黑 `#110F0C`，加一层固定种子的印刷颗粒（每次导出一致）和轻暗角；去掉圆角面板，三段之间只画 1px 细线。卡图保留完整卡面和原比例，加柔和投影，不倾斜；卡画模式不再裁成画带，也按原比例放入。卡面不铺成背景
- 强调色不再固定为钴蓝：从“最喜欢的设计”那张卡画的插画区域取像素，按色相加权找主色，压到 30% 饱和度、66% 明度，只画标题短线和三个小记号，文字一律用暖灰层级；读不到像素时用暖灰 `#AD9C7E`
- 底部参与区：左侧是邀请语“这是我看待万智牌的方式，你呢？”、“长按识别小程序码，选出你的三张牌”、版权和去重后的画师署名；右侧 156px 白底方块放小程序码，和文字、边缘都留出空白
- 排版细节：画布高度按内容计算，长署名、长牌名和三行短评先量好再定高度，互不遮挡；折成多行的文字在不增加行数的前提下收窄行宽，末行不再只剩一两个字，逗号句号不放在行首。导出时按画布尺寸输出，不随屏幕像素密度放大

标签写进名片契约（`PASSPORT_TAGS`、`passportTags`、`tagLabels`），云函数副本已同步。线上 community 云函数仍是旧版本，重新部署之前，服务端校验会丢掉分享名片里的标签；本机草稿与海报不受影响。

验证：无头 Edge 加载实际的 `contracts.js` 与 `poster.js`，把画布位图原样导出，逐张查看有署名英文版、中文印刷版、无署名、长文本和卡画五种情况。浏览器里中文是微软雅黑，手机上是系统字体，字宽略有差别，最终以真机导出为准。

## 粒子、玻璃与开手题（2026-09-14）

用户要求六页与竞逐时空补上其他功能页的背景粒子，文字框改用玻璃层，并换掉自拟的开手题。本节优先于后文“无持续粒子背景”的旧取舍。

- 粒子：六页挂载 `particle-background palette="tracker"`（与“我的主将”同色），正文包进 `content-layer`。画布是固定定位，不包的话非定位内容会被画在画布下面，点击也落到画布上；系统开启减弱动态效果时画布照旧隐藏
- 玻璃：面板、名片选牌区与起手牌格挂 `.surface`，吃 dark-table 的顶部高光与柔和投影；输入框统一用 `input-glass`、`hairline` 与 `radius-2`，对局约定的选择框改用输入玻璃底。赛后一分钟的输入框也从不透明深色换成同一套玻璃底
- 禁牌表：列表不再逐张显示“禁用”，只保留 Lutri 的“仅禁作行侣”；读屏标签同样只念出例外状态，详情页的状态徽标不变
- 赛后一分钟：入口去掉“选填”；保存后对局记录行挂“复盘”标签，点开在行下显示填过的几项，刚保存的那局默认展开；只点开没写字的不存成空复盘
- 这手留不留：十手来自 Play to Win 播客的起手测试与 Matt Sperling 的 TopDeck.gg 文章，去掉“二地加互动”这类自拟标题，改列主将、座次、调度阶段与对手。理由沿用调度、免费调度、先手牌手、互动、打法等官方或社区已有的词，按回合写出法术力从哪来，并附来源链接

服务 UX Goals B（跨页一致）、D 与 F（保存后能看到复盘去了哪里）、H（开手判断标明出处，不冒充唯一答案）。代价：持续绘制的粒子会增加阅读页耗电与视觉干扰，由组件既有的帧率降档、内存告警降档与减弱动态效果设置兜底；开手题换了新 ID，旧题的历史票数不再显示，云函数重新部署后新题才能投票。

## 入口页精简（2026-09-14）

## 这手留不留改用试玩手牌区（2026-09-14）

按用户要求，七张牌改用套牌试玩手牌区的设计：暗色横条里放 66 × 92 的卡图瓦片，样式照搬试玩页，七张同样大小，测试按试玩页的瓦片尺寸比对。手机宽 375 时一屏约放下四张半，其余横向滑动；瓦片上的牌名看不清，点任意一张用系统大图预览，可左右滑看全部七张。卡图直链由 `scripts/build-hand-card-index.js` 单批查询 Scryfall 生成 `shared/hand-cards.js` 随包提供，打开页面不发卡图请求；换题后要重跑脚本，测试会挡住缺图或印刷版本对不上。页面底部补了卡图与版权署名。

## 牌友名片不再对照（2026-09-14）

用户认为牌友分享后逐项对照没有必要：万智牌太多，两个人很难选到同一张，“不同选择”几乎是唯一结果。打开牌友的分享名片时，现在只显示对方的三张卡图，以及每一类下的牌名和短评；“我的选择 / 对方的选择”面板和“同牌同版本 / 同牌不同版本 / 不同选择”标记去掉，`contracts.js` 里只供对照使用的 `compare` 一并删除。云函数从未调用它，服务端行为不变。

## 名片海报深暗极简（2026-09-14）

按用户要求用 kimi-inspired-poster 技能的“信息图 / PPT 配图”分支重做：牌名、短评、署名都是用户的原文，必须由代码精确排版，不能交给生图模型。版式取并列事实的 `cards`，配色取 `signal-panel` 的冷黑面板。

- 去掉三段金、青灰、陶粉色条，去掉右上角大号“03”和每段右上的序号；三类选牌已由面板里的小标签说明

- 标题和牌名不用粗体，层级靠字号、间距和留白；小号标签逐字加字距，因为微信 Canvas 不保证支持 `letterSpacing`
- 三块面板同样大小，与“这手留不留”牌格等大的取舍一致，不暗示哪一张更重要；这偏离了技能“只突出一个模块”的默认建议
- 卡画模式从铺满面板改为左侧画带；卡图保留原色，它是内容本身，外壳保持单色
- 没署名时标题已是“我的三张牌”，不再重复“三张牌认识我”

验证：用无头 Edge 加载实际的 `poster.js`，在浏览器 Canvas 上画出全卡、卡画、无署名和长文本四种情况并逐张查看。浏览器里中文是微软雅黑，手机上是系统字体，字宽会略有差别，最终效果仍以真机导出为准。

## 这手留不留精简（2026-09-14）

- 七张牌格同宽同高：去掉最后一张独占整行的样式，行高取最长牌名那一格，不让某张牌显得更重要
- 去掉副标题说明和“用我的套牌练习”跳转；选择器标签只留序号和主将，座次放在对局条件里
- 投票组件加 `compact`：练习题点选项即投票，不显示赛制、理由、投票、撤票和刷新按钮，投过票才显示社区比例，避免先看票数再作答
- “投票选项已变化，请刷新”的成因：上一轮换题后云函数还没重新部署，服务端不认新题号，读取票数时返回 `INVALID_VOTE`，于是每道题一进来都报这句，而刷新并不能解决。现在服务端不认题号时整块投票安静收起、不发投票请求；禁牌表遇到同样情况只显示“这一轮投票暂未开放”

- **入口**：EDH hub 取代牌友空间；空名片展示示例牌面，已有完整玩家名片展示自己的选择。三张牌入口与四个工具分组。
