# EDH 牌桌设计审查

本轮按用户要求先评分，再逐页重构。设计判据来自 bencium-controlled-ux-designer、README「视觉规则」「改动口径」及 docs/ux-goals.md；文案按 stop-slop 检查。下表是对照同一标准的设计自评，不代表外部团队或真机用户评分。

## 粒子、玻璃与开手题（2026-09-14）

用户要求六页与竞逐时空补上其他功能页的背景粒子，文字框改用玻璃层，并换掉自拟的开手题。本节优先于后文“无持续粒子背景”的旧取舍。

- 粒子：六页挂载 `particle-background palette="tracker"`（与“我的主将”同色），正文包进 `content-layer`。画布是固定定位，不包的话非定位内容会被画在画布下面，点击也落到画布上；系统开启减弱动态效果时画布照旧隐藏
- 玻璃：面板、名片选牌区与起手牌格挂 `.surface`，吃 dark-table 的顶部高光与柔和投影；输入框统一用 `input-glass`、`hairline` 与 `radius-2`，对局约定的选择框改用输入玻璃底。赛后一分钟的输入框也从不透明深色换成同一套玻璃底
- 禁牌表：列表不再逐张显示“禁用”，只保留 Lutri 的“仅禁作行侣”；读屏标签同样只念出例外状态，详情页的状态徽标不变
- 赛后一分钟：入口去掉“选填”；保存后对局记录行挂“复盘”标签，点开在行下显示填过的几项，刚保存的那局默认展开；只点开没写字的不存成空复盘
- 这手留不留：十手来自 Play to Win 播客的起手测试与 Matt Sperling 的 TopDeck.gg 文章，去掉“二地加互动”这类自拟标题，改列主将、座次、调度阶段与对手。理由沿用调度、免费调度、先手牌手、互动、打法等官方或社区已有的词，按回合写出法术力从哪来，并附来源链接

服务 UX Goals B（跨页一致）、D 与 F（保存后能看到复盘去了哪里）、H（开手判断标明出处，不冒充唯一答案）。代价：持续绘制的粒子会增加阅读页耗电与视觉干扰，由组件既有的帧率降档、内存告警降档与减弱动态效果设置兜底；开手题换了新 ID，旧题的历史票数不再显示，云函数重新部署后新题才能投票。

## 入口页精简（2026-09-14）

- 三张牌入口只留“我的三张牌”标签、卡图和标题：三类选牌说明字多，也难与三张倾斜的卡图对齐，因此去掉；“编辑我的名片 →”一行去掉，未保存时同一行的“选出我的三张牌”一并去掉，整张卡本身就是按钮，右上角箭头保留
- 对局约定的标签由“开局”改为“条约”
- 去掉通往战绩页的“对局复盘”链接，不在小程序里重复导航；赛后一分钟仍在“我的主将”的对局记录里填写和查看

## 三张牌名片：小程序码、提示语与选牌（2026-09-14）

- 海报右上角加小程序码：白底圆角方块保证长按能识别，下附一行“长按识别，选出你的三张牌”；标题宽度收窄到说明文字左侧，长署名折行也不会压到二维码
- 填写提示改成让人想分享的问法：三格分别是“看一眼就心动的那张”“牌友一看就知道你怎么玩的那张”“每次打出来都让全桌愣一下的那张”；署名提示“牌桌上大家怎么叫你，不填也行”，短评提示“为什么是它？一句话让牌友懂你”
- 选牌弹层记住是为哪个问题打开的：换一格时清空上次的搜索词、结果、版本页和语言，从头搜索，省掉手动清空这一步；同一格误关再打开仍保留上次结果。调牌记录的换出与换入同样按目标区分

## 这手留不留改用试玩手牌区（2026-09-14）

按用户要求，七张牌改用套牌试玩手牌区的设计：暗色横条里放 66 × 92 的卡图瓦片，样式照搬试玩页，七张同样大小，测试按试玩页的瓦片尺寸比对。手机宽 375 时一屏约放下四张半，其余横向滑动；瓦片上的牌名看不清，点任意一张用系统大图预览，可左右滑看全部七张。卡图直链由 `scripts/build-hand-card-index.js` 单批查询 Scryfall 生成 `shared/hand-cards.js` 随包提供，打开页面不发卡图请求；换题后要重跑脚本，测试会挡住缺图或印刷版本对不上。页面底部补了卡图与版权署名。

## 牌友名片不再对照（2026-09-14）

用户认为牌友分享后逐项对照没有必要：万智牌太多，两个人很难选到同一张，“不同选择”几乎是唯一结果。打开牌友的分享名片时，现在只显示对方的三张卡图，以及每一类下的牌名和短评；“我的选择 / 对方的选择”面板和“同牌同版本 / 同牌不同版本 / 不同选择”标记去掉，`contracts.js` 里只供对照使用的 `compare` 一并删除。云函数从未调用它，服务端行为不变。

## 名片海报深暗极简（2026-09-14）

按用户要求用 kimi-inspired-poster 技能的“信息图 / PPT 配图”分支重做：牌名、短评、署名都是用户的原文，必须由代码精确排版，不能交给生图模型。版式取并列事实的 `cards`，配色取 `signal-panel` 的冷黑面板。

- 去掉三段金、青灰、陶粉色条，去掉右上角大号“03”和每段右上的序号；三类选牌已由面板里的小标签说明
- 冷黑底 `#050507`、面板 `#0C0E12`；文字分四级：标题银白、正文冷灰、标签更暗、版本号用等宽小字；钴蓝只出现一次，是标题块下 40 px 的短线
- 标题和牌名不用粗体，层级靠字号、间距和留白；小号标签逐字加字距，因为微信 Canvas 不保证支持 `letterSpacing`
- 三块面板同样大小，与“这手留不留”牌格等大的取舍一致，不暗示哪一张更重要；这偏离了技能“只突出一个模块”的默认建议
- 卡画模式从铺满面板改为左侧画带；卡图保留原色，它是内容本身，外壳保持单色
- 没署名时标题已是“我的三张牌”，不再重复“三张牌认识我”

验证：用无头 Edge 加载实际的 `poster.js`，在浏览器 Canvas 上画出全卡、卡画、无署名和长文本四种情况并逐张查看。浏览器里中文是微软雅黑，手机上是系统字体，字宽会略有差别，最终效果仍以真机导出为准。

## 这手留不留精简（2026-09-14）

- 七张牌格同宽同高：去掉最后一张独占整行的样式，行高取最长牌名那一格，不让某张牌显得更重要
- 去掉副标题说明和“用我的套牌练习”跳转；选择器标签只留序号和主将，座次放在对局条件里
- 投票组件加 `compact`：练习题点选项即投票，不显示赛制、理由、投票、撤票和刷新按钮，投过票才显示社区比例，避免先看票数再作答
- “投票选项已变化，请刷新”的成因：上一轮换题后云函数还没重新部署，服务端不认新题号，读取票数时返回 `INVALID_VOTE`，于是每道题一进来都报这句，而刷新并不能解决。现在服务端不认题号时整块投票安静收起、不发投票请求；禁牌表遇到同样情况只显示“这一轮投票暂未开放”

## 使用门槛与文案修正（2026-09-13）

用户反馈上一版限制过多、用语生硬。此前自评未充分反映这些问题，以下修正优先于后文的首轮设计记录：

- 署名、短评选填，选齐三张牌即可导出或分享；无署名海报显示“我的三张牌”
- 调牌不再要求关联套牌或写目标，可记同牌不同印刷版本的替换；去掉 100 条人为上限，默认随时复盘，关联战绩后才可选择按场数提醒
- 新桌默认允许代牌、无限组合技和额外回合；旧约定保持原值，不替玩家改已保存的选择
- 投票只需选择立场，赛制和理由收进选填区；未填赛制归入 unspecified，不推断为“两者都玩”，旧票数继续兼容；本地选择保存失败不再阻断在线投票
- 删除重复须知和说教提示，用“代表打法的牌”“没问题”“停止分享”等直接表达；保留影响操作结果的错误提示、官方禁牌范围和版本更新说明

新增回归检查覆盖无署名分享、空文字、选填投票信息及旧统计迁移。微信内容审核仍检查玩家填写的文字；牌张仍从真实印刷版本解析，所有权和投票去重保持原有行为。

| 维度 | 权重 | 原版 | 本轮 | 对应改动 |
| --- | --- | --- | --- | --- |
| 主任务与信息层级 | 20% | 6 | 8.5 | 删除首页口号和装饰序号，突出三张牌名片，工具入口分组 |
| 跨页面一致性 | 20% | 6 | 9 | 接入 dark-table 主题、全站字体、按钮 token 与 pressable-active |
| 卡牌识别 | 20% | 3 | 9 | 禁牌直接展示卡图，版本搜索使用小档缩略图，调牌显示换入换出 |
| 移动阅读与触控 | 15% | 7 | 8 | 输入字号 16px，正文 14px，按钮和选择器最小热区 44px |
| 社群用语与信息密度 | 15% | 5 | 9 | EDH 牌桌、禁牌表、对局约定、调牌记录，统一“组合技” |
| 操作与恢复 | 10% | 8 | 8 | 保留本机草稿、改票撤票、作者撤回、卡图失败重试 |

加权自评从 5.6/10 提升至 8.7/10。剩余分数主要留给手机相册、真实弱网、双用户分享及长期使用反馈。

## 逐页修改

- **入口**：EDH 牌桌取代牌友空间；空名片展示示例牌面，已有完整玩家名片展示自己的选择。三张牌入口与四个工具分组。
- **禁牌表**：43 张牌的真实印刷 ID 与卡图直链随包提供，进入列表不逐张请求元数据。二列整卡展示，点击进入完整卡图和投票。Lutri 保留仅限行侣的状态，不改变投票 ID 和历史票数。
- **名片**：三张独立选牌区，分别解释最佳设计、打法代表和常用妙妙牌。保留真实卡画、语言和短评；去除举报及其后端入口。
- **对局约定**：选项按标签与当前值排列，删除不承载功能的编号；保留版本变更后重新确认的说明。
- **调牌记录**：换出与换入并列显示卡图，观察状态和场数分行；编辑和战绩仍用同一数据来源。
- **开手讨论**：起手七张紧凑排列，座次与调度条件分行；讨论用留牌、调度、法术力、互动和组合技等现有词汇。

## README 对齐与取舍

| 项目要求 | 处理 |
| --- | --- |
| 网络图占位、延迟加载、高度确定 | 分包图片补齐 lazy-load 与暗色占位；整卡、缩略图和画廊明确高度；海报宽高由 750×1200 导出决定 |
| 按格子选择图片档位 | 禁牌二列卡面约 174 CSS px，3 倍屏约 522px，保留 normal 档；选牌弹层的小图使用 small 档并兼容旧记录 |
| 共用主题与反馈 | 金色强调集中在 dark-table；操作按钮消费 --cedh-btn-*；组件使用 apply-shared 接入全站按压反馈 |
| 微信原生按钮 | 局部显式 width、margin、禁用背景，避免 184px 默认宽度与白底 |
| 可读性与热区 | 功能文字满足 4.5:1 对比度目标；按钮与 picker 44px 下限；实际布局检查窄屏和放大字体 |
| 短提示与完整语义 | 自编 UI 去除装饰中点、圆点、句末点号与省略号；规则原文、牌名、网址、用户输入保留原样 |
| 删除功能的范围 | 删除举报按钮、处理器与云端 report 分支；保留内容审核、所有权检查和作者撤回 |
| 共用战绩 | 新区的对局复盘仍进入原 tracker，不另建战绩库 |
| 可回退与数据诚实 | 卡图失败显示占位并可重试；投票显示真实服务结果；未提交的本机选择不计入社区 |

服务 UX Goals A/B/F/G：突出任务、识别卡牌、统一反馈与提升可读性。代价是卡图比纯文字列表占空间和流量，通过静态索引与延迟加载控制请求；六页保留内容所需的结构差异，不强行做成相同表单。首轮沿用竞逐时空的无持续粒子背景取舍；2026-09-14 起按用户要求改为挂载粒子背景，见文首。

## Stop-slop 检查

自评 44/50：直接性 9、节奏 8、信任读者 9、自然度 9、信息密度 9。删除“牌局之外，也有好故事”等口号及重复解释；提示说明当前动作。保留主将、互动、妙妙牌等本项目与用户已使用的词，不凭语感发明术语。规则关键词与牌张正文不随视觉清理删改。

## 验收口径

2026-09-13 完成以下验证：

- `npm run check`：128 个 JavaScript 文件语法检查、335 项测试及严格推荐诊断通过，deadCount 为 0
- 微信原生编译：23 个 WXML、29 个 WXSS 通过；开发者工具 SDK 3.17.3 中六页运行无页面错误
- 布局：320/375/430px 的八种页面状态共 24 组检查通过；320px 使用 135% 字号，未发现检查范围内的文字溢出或小于 44px 的按钮；另查看原生截图
- 真实选牌：Sol Ring 搜索返回 10 项、简中印刷返回 20 项，所选语言及本机草稿恢复正确；海报成功导出为 750×1200
- 禁牌：原生列表 43 张牌，卡图失败状态与重试清理通过；Lutri 仍显示“维持行侣禁令”
- 云端：community 部署成功，状态 Active、超时 30 秒；真实调用已删除的 report 操作返回 `ok: false, code: INVALID_INPUT`；正常投票读取成功

开发者工具、浏览器布局验证、云函数部署和开发版上传分别留证。上述结果不代替手机相册、真实弱网和两位玩家的分享验收；开发版上传版本与源提交以交付回执为准。
