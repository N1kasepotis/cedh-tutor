# Planechase UI 技能审查与复核记录

2026-09-09。对照基线：`2a32be0`。范围：竞逐时空页面的布局、阅读、按钮与错误恢复。规则 reducer、官方牌张文字和 schema 2 存档格式不变。

## 使用的技能与适用边界

按用户指定的 [Snyk 技能清单](https://snyk.io/articles/top-claude-skills-ui-ux-engineers/#8-vercel-react-native-skills)，读取原始技能规范后应用：

| 技能 | 本轮应用 | 技术边界 |
| --- | --- | --- |
| [Vercel Web Design Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md) | 长文本、真实图片尺寸、焦点反馈、错误入口可见性、持续动效、底栏与安全区 | 使用 WXML / WXSS 对应能力；浏览器检查不能认证微信读屏 |
| [Bencium UX Designer](https://github.com/bencium/bencium-claude-code-design-skill) | 按任务频率分配空间、减少重复动作、保留共享主题与渐进展示 | 用户已指定整体一致性及执行优化；不套入其 Tailwind / shadcn 技术栈 |
| [Vercel React Native Skills](https://github.com/vercel-labs/agent-skills/blob/main/skills/react-native-skills/SKILL.md) | 对照图片、滚动安全区和移动端性能原则 | 当前是微信原生小程序；未引入 React Native、Expo、FlashList，未宣称获得这些库的优化 |

未安装或运行 AccessLint，也未把人工规则检查描述为自动 WCAG 认证。

## 已修复的问题

| 位置 | 问题与结果 | 取舍 |
| --- | --- | --- |
| `planechase.wxss` / `.plane-art` | 通用 `button:not([size=mini]) { width: auto }` 压过卡图宽度；图片已加载但按钮与图片宽度为 0。补充页面内更具体的 `width: 100%` | 保留其他按钮的原生宽度修正，避免再次挤压骰子读数 |
| `planechase.wxml` / 页首 | 三格统计比掷骰状态更显眼，回合按钮位于整段卡文之后。人数和牌库余量并入标题下方，骰子及回合控制前置；当前牌数由页签呈现 | 服务 UX Goals A/C 的操作效率，减少重复统计的视觉分量 |
| `planechase.wxml` / 单来源结算 | 同一动作在卡内与底栏重复。单条来源只留底栏；多条来源保留逐条结算及反击/复制入口 | 单条减少决策，多条仍由玩家选择，不替玩家决定堆叠顺序 |
| `planechase.js` / `commit` | 长卡文底部操作失败后，恢复按钮可能在屏幕之外。失败状态渲染后滚动至 `#save-notice` | 失败不推进牌局、不重掷骰；保留卸载及弹层保护 |
| `planechase.wxml` / 背景 | 装饰连线持续穿过阅读区，降低透明度仍持续绘制。该页取消画布挂载 | 服务 UX Goals A/D 的专注与资源节制；共享颜色、材质、字体不变，其他页动效不变 |
| `planechase.wxss` / 弹层与按钮 | 增加四侧安全区留白、短屏弹层滚动上限及 2px 可见键盘焦点 | 使用平台 CSS 能力，手机系统缩放和读屏仍须原生验收 |

普通掷骰时机说明移至对局设置；即时费用继续显示在主操作按钮。官方卡文、置底提示及响应时机未裁剪。

## 可复核的证据

- 预览使用实际页面控制器、原生 WXML 编译产物和从微信基础库提取的 `style: v2` 按钮默认规则；存储、导航和图片失败使用隔离适配。
- 375px 普通字体下，卡图按钮从 **0px** 修复到 **318px** 宽，图片完成加载；掷骰控制区由页面 y≈723px 移至 y=108px。第一张卡从 y≈281px 调整为 y=270px。
- 320px、135% 字体检查：未掷骰、旧存档提示、空白改判、多来源、置底排序、保存失败、卡图弹层失败、长卡文、卡图离线，共 9 组。
- 375px / 430px、135% 字体分别检查：未掷骰、空白改判、多张时空、卡图弹层，共 8 组。
- 320px / 375px / 430px 普通字体复核首屏，共 3 组。以上布局未见横向溢出、骰面文字裁切、白色禁用按钮或不足 44px 的已渲染按钮。
- 812×375 横屏、135% 字体下，弹层上下边界约 y=28/347px，内部滚动区 215px，内容 653px；关闭按钮位于可见区域。
- 实际点击确认：保存失败重试后仍停留原牌局，恢复入口回到视口；取消后主按钮可用；单条能力从底栏结算，撤销后恢复原待结算状态；Tab 聚焦按钮显示 2px 焦点描边。
- 自动回归沿用现有存储失败测试，增加恢复入口滚动断言；未增加仅复述样式的测试。
- 最终本地检查：320 项测试全部通过、104 个 JavaScript 文件语法通过、严格诊断通过；全部 15 个 WXML / 20 个 WXSS 原生编译通过。

这些是本地编译与浏览器适配证据，不是微信真机截图或端到端认证。开发者工具服务端口当前为 Off，未取得新的微信上传成功响应。

## Claude / 开发团队复核入口

1. 从项目根导入微信开发者工具，打开 `pages/planechase/planechase`。先核对卡图真实可见、字体与共享功能页一致、原生禁用按钮仍为深色。
2. 掷出换境或混沌后，核对一次点击只执行当前按钮含义；切回卡文再点击底栏，应先回结算台。复制触发后逐条选择，不能自动处理全部来源。
3. 在长卡文底部制造保存失败，核对错误与重试入口进入视口；重试不改变已抽到的随机结果，取消不推进牌局。
4. 在 iOS / Android 验证大字体、底部手势区、横屏卡面、滚动至末尾和屏幕阅读器。需记录设备、微信版本和问题截图；本轮未替代此项。

自动检查命令：`node scripts/check-syntax.js`、`node --test tests/*.js`、`node scripts/diagnose-coverage.js --strict`。原生编译覆盖全部 WXML / WXSS。最终 Git 提交与 CI 结果以交付记录为准。
